## 三、待拍板决策（主理人无权代决）

1. **数值重铸是否成套上**：S-02 的 5 条、S-01 的 3 条必须一起落地，单独上任意一条都会被其他放大器吃掉。接受成套修，还是先只修 P0？
2. **HOUSE_INDEX 设计取向**（涉及设计，需策划侧）：① 房价指数 2025: 6.9→12、2060: 9.85→20；② **不动房价**，给自住房 `SEC+8 / MOOD+6 / 每年 STRESS−3`，把买房从纯财务决策变成「财务略亏 + 生活增益」的真取舍。
3. **音频三项**：① 是否接受「全程序化合成、0 音频文件」；② SFX 默认开还是关（建议开 + 显著静音键）；③ 本阶段是否不做 BGM（读多听少，睡前/通勤/摸鱼三大「不能被打扰」场景）。
4. **无障碍目标级别**：是否定 **Standard**（P0 三项 + focus-visible，P1 reduced-motion + 触控≥40px，约 1–1.5 人日纯 CSS）。
5. **头像视觉收敛方案**：A 全量卡通化 / **B 容器加描边（推荐，6 行 CSS）** / C 半描边。
6. **是否授权落地 `assets/` 改动**：四位成员**均未修改任何源码**，全部方案待授权。

## 四、已知风险与缓解

| 级 | 风险 | 缓解 |
|---|---|---|
| 🔴 | **小程序静默失效**：改逻辑层 7 文件后必须跑 `node tools/build-engine.js`，否则小程序停在旧版**且不报任何错** | 立即写进发布 checklist；禁止新增/删除/重命名逻辑层文件（脚本写死 7 个文件名，故「拆分 data.js 懒加载」是禁选项） |
| 🔴 | **S-02 与 S-03 互相抵消**：先修评分再修经济会白做 | 严格按 `A-07 → S-02 → S-03` 顺序，每步后重跑 `playtest-run.js` 校准 |
| 🟡 | **jsdom 测不出真机表现**：`localStorage.setItem` 3–15ms、×5 安卓换算系数均为估算 | 收尾必须补真机验证：两台不同档位安卓各 3 次，含 iPhone 静音键开/关两态 |
| 🟡 | **老存档迁移零测试**：2780 局全是新开局，`migrateState()` 链路未覆盖 | 发布前单独补（REG-13），不跟随迭代 |
| 🟡 | **O-03 丢档风险**：节流后若缺 `pagehide` 兜底，手机切后台会真丢存档 | 该兜底为落地前置条件，非可选 |
| 🟡 | **结论基于脚本画像非真人**：真实休闲玩家更接近 baseline 画像（买房率 0%） | 若目标用户就是随手乱点的休闲玩家，S-02 体感严重度可下调一级 |
