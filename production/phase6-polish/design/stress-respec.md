## 0. 三件套声明（⛔ 禁止拆散上）

> **① 恢复公式 + ② `scaleEff` 不对称化 + ③ 主动减压行动，三条必须成套上。**
>
> 拆任何一条都会留下半个系统，且会产生新的失败态：
> - 只上 ①：STRESS 有稳态了，但高风险仍是**净负期望** → 激进流依然必死，只是死得慢一点。
> - 只上 ②：高风险变成净正期望，但 STRESS 仍**线性累积无稳态** → 激进流死得更晚但照样死，且「健康流」与「激进流」差距被拉大到不可弥合。
> - 只上 ③：多了一个 −12/年的按钮，但流入端没改、恢复端没改 → 只是把死亡线从 36.9 岁推到 45 岁，且减压按钮会因为「每年必按」退化成**无决策的仪式**（SDT 自主感反而下降）。
>
> 三条是一道方程的三个项：**① 给系统一个稳态，② 让「勇敢」从必死变成高方差的正期望，③ 给玩家一个主动的、有叙事质感的阀门。**

## 1. 现状与根因

| 现象（实测） | 数值 |
|---|---|
| 激进流平均寿命 | **36.9 岁** |
| 激进流熄灭率 | **67%** |
| STRESS 恢复 | `s.STRESS = Math.max(0, s.STRESS - 7)`（engine.js:1484）——**固定 −7/年，无比例项** |
| 风险放大 | `scaleEff(base, 1.7, 1.35)` —— 增益 ×1.7、减益 ×1.35，**近似对称** |
| 成年后主动减压手段 | **0**（`UNI_ACTIVITIES` 的 `a_sport {STR:6,HP:6,STRESS:-5}` 毕业后消失） |
| STRESS / HP 上限 | 120 / 120 |

### 1.1 根因一：恢复是无稳态的线性衰减

现状 `S_{t+1} = S_t + I − 7`（`I` = 年 STRESS 流入）。只要 `I > 7`，STRESS 就**线性无界增长**，直到撞上 120 上限。
`I = 15` → 约 15 年撞顶；`I = 35` → 约 4.3 年撞顶。这解释了「激进流 36.9 岁」。

### 1.2 根因二：对称放大 + 一次性增益 vs 累积性减益

`scaleEff(base, 1.7, 1.35)` 的增益/减益比 = 1.7 / 1.35 = **1.26**。
**收益是一次性的（MONEY / FAME / INT 拿到就结束），压力是累积的（STRESS 每年叠加）**。对称放大等于把「一次性」和「累积性」按同一个系数放大 → 长期必然净负。

用赔率门槛量化（`gamble p ≈ 0.45`）：

| 口径 | 期望值 | 「值得一赌」的赔率门槛（W/L） |
|---|---|---|
| 现状 `1.7 / 1.35` | `0.45×1.7×W − 0.55×1.35×L = 0.765W − 0.743L` | **W/L > 0.97**（≈「必胜才值得」） |
| 修复 `2.4 / 1.15` | `0.45×2.4×W − 0.55×1.15×L = 1.08W − 0.633L` | **W/L > 0.58** |

> 修复后，风险选项的可行性门槛从「必胜」降到「赔率 0.58」。**勇敢从「必死」变成「高方差的正期望」**——这正是「人生模拟器」应有的样子。

### 1.3 根因三：成年后无任何主动减压手段

`GOOD_DEEDS`（data.js:1786-1827）8 条全部是 **ETH / 道德**向，STRESS 减免只有 `g_apology −5` 与 `g_quit −6` 两条，且是顺带的。
`socialAct`（engine.js:158-233）是**关系**向，STRESS 只 −2~−4，且绑定具体关系对象（没朋友就不能用）。
大学期间的 `a_sport`（school.js）毕业后消失。

**结果：22 岁之后，玩家对「我压力很大」这件事完全无能为力。** 这是 SDT 自主感从 7 掉下来的直接原因，也是「压力棘轮」这个比喻成立的地方——只能进，不能出。

## 2. 三件套设计

### ① 恢复公式：固定 −7 → **固定 + 比例**

```js
// engine.js:1484  yearBase()
// 现状
s.STRESS = Math.max(0, s.STRESS - 7);

// 修复（方案 D 定稿：阈值以下逐点不变，只压失控尾巴，见 §3.0）
const over = Math.max(0, s.STRESS - STRESS_DAMP_T);
s.STRESS = Math.max(0, s.STRESS - (STRESS_RECOVER_FLAT
                                 + s.STRESS * STRESS_RECOVER_K
                                 + over * STRESS_DAMP_Q));
```

| 参数 | 值 | 说明 |
|---|---|---|
| `STRESS_RECOVER_FLAT` | `7` | 固定项不变 |
| `STRESS_RECOVER_K` | **`0.12`（定稿，不再改动）** | 比例项。压力大时恢复更快——符合「触底反弹」的真实心理，也让系统有稳态。**方案 A（提到 0.20）已被 team-lead 否决**：它会把 `I=28` 的正常玩家 `S*` 从 50 削到 30 |
| `STRESS_DAMP_T` | **`70`（新增，定稿）** | 阻尼阈值。低于此值恢复公式与今天**逐点相同** |
| `STRESS_DAMP_Q` | **`0.25`（暂定，等实测 `I`）** | 阻尼系数。拟合式 `q = clamp((I_P75 − 34)/30, 0, 0.35)` |

**稳态推导**：`S* = (I − 7) / 0.12`（`I` = 年 STRESS 流入）

| `I` | 现状（无稳态，撞顶年限） | 修复后稳态 `S*` |
|---|---|---|
| 15 | 120（约 15 年） | 67 |
| 25 | 120（约 6.7 年） | 150 ⚠️ |
| 35 | 120（约 4.3 年） | 233 ⚠️ |

> ⚠️ **单独上 ① 不足以救激进流**（`I ≥ 25` 时稳态仍超上限）。这正是「禁止拆散」的数学依据：必须靠 ② 把 `I` 压下来、靠 ③ 再减 12/年。

### ② `scaleEff` 不对称化：增益 `1.7 → 2.4`、减益 `1.35 → 1.15`

```js
// engine.js:1012  eventChoices()
// 现状
const risk3 = Object.assign(scaleEff(base, 1.7, 1.35), { STRESS: (base.STRESS || 0) + 4 });

// 修复
const risk3 = Object.assign(scaleEff(base, RISK_GAIN_K, RISK_LOSS_K), { STRESS: (base.STRESS || 0) + RISK_STRESS_ADD });
```

| 参数 | 现值 | 修复值 | 理由 |
|---|---|---|---|
| `RISK_GAIN_K` | 1.7 | **2.4** | 让「豁出去」的收益足够大，值得为之承压 |
| `RISK_LOSS_K` | 1.35 | **1.15** | 减益只轻微放大（1.15 ≈ 惩罚仍在但不致命） |
| `RISK_STRESS_ADD` | 4 | **4（不变）** —— ⚠️ **方向：中性·不降** | **它不在 `scaleEff` 的管辖范围内，因此 ② 对 STRESS 流入 `I` 的影响精确等于 0。**<br>机制：`Object.assign(scaleEff(base,...), { STRESS: (base.STRESS\|\|0) + RISK_STRESS_ADD })` —— `Object.assign` 的**后写覆盖先写**，STRESS 是覆盖赋值，`gainK` / `lossK` 都碰不到它。<br>→ `RISK_GAIN_K 2.4` 打不到它（否则 +4 会变成 +10，反而加剧棘轮）；`RISK_LOSS_K 1.15` 也打不到它。<br>→ **② 救的是「HP / MONEY / MOOD 耗不起」，不是「压力大」。降 STRESS 只能靠 ① 与 ③。**<br>⚠️ 若工程侧把 STRESS 改成经 `scaleEff` 计算，**必须显式保持 +4 原值** |
| 增益/减益比 | 1.26 | **2.09** | 从「近似对称」到「明确正期望」 |

**连带影响（必须一并检查）**：`scaleEff` 只被 `eventChoices()` 的 risk3 使用（engine.js:1012）。请 engineering-lead 用 `rg "scaleEff\("` 全量确认，**若存在其他调用点，需逐点确认是否共用新系数**——共用会让手写选项事件也被放大。

#### 3.3 一年一次限制

```js
state.relaxUsedYear = 0;   // 在 yearBase / advanceYear 处每年重置
// 三个行动共享同一个年度额度：一年内只能做其中 1 件
```

**为什么共享额度而不是各一次**：若各一次，理论年减压 = −38，叠加恢复公式会把 STRESS 打到 0，压力系统失去意义。共享额度下理论年减压 = −16（最优解），**且玩家必须在「社交 / 身体 / 专业帮助」之间做选择**——这个选择本身就是设计内容（SDT 自主感 +1）。

#### 3.4 与现有系统的去重边界（关键）

| 系统 | 目的 | 收益主轴 | STRESS 减免 | 年度限制 | 与 `RELAX_ACTS` 的边界 |
|---|---|---|---|---|---|
| `GOOD_DEEDS`（8 条） | **攒 ETH（道德）** | `ETH` 为主，`MOOD/LOVE` 顺带 | `g_apology −5`、`g_quit −6`（顺带，非主轴） | 无 | **不冲突**。善事是「**对外付出**」，减压是「**对自己**」。善事不占用减压额度 |
| `socialAct`（父母/配偶/子女/宠物/朋友） | **维护关系值** | `LOVE` / 关系值 | −2 ~ −4 | 无 | ⚠️ **唯一重叠点**：「朋友」项与 `r_friends` 功能相似 |
| 新增 `RELAX_ACTS` | **系统性降 STRESS** | `STRESS` / `HP` / `MOOD` | **−10 ~ −16** | **每年 1 次（三选一）** | — |

**边界处理（3 条硬规则）**：

1. **语义切分**：`socialAct` 是「**维护一段具体关系**」（有对象、有反馈、有冷却）；`RELAX_ACTS` 是「**照顾自己**」（无对象、即时生效）。
2. **`socialAct` 的「朋友」项保留，但降权**：STRESS 减免 −3 → **−1**，并把文案从「约朋友出来」改为「**给老朋友发条消息**」——明确它是轻量维护，不是系统性减压。
3. **`GOOD_DEEDS` 中 STRESS 减免 > 5 的两条保留但标注**：`g_apology`（−5）与 `g_quit`（−6）不占用减压额度，但在 UI 上归入「善事」分区，避免玩家把二者混为一谈。

## 3. 组合后的稳态推演

### 3.0 ✅ 方向核验（**v1.1，应 team-lead 要求逐参数核符号**）

> **结论：S-01 是「降」，不是「升」。全部参数无一处在升 STRESS。**
> **但核出一条机制错误：② 对 STRESS 是「中性」而非「降」，而 §3 的推演错误地把它当成了降 `I` 的手段 —— 幅度因此不足以达成 S-1/S-2。**

**逐参数方向核验表：**

| 参数 | 改动 | 对 STRESS 的方向 | 判定 |
|---|---|---|---|
| ① `恢复 = 7 + 0.12×S` | 恢复量 **变大** | **降** ✅ | 正确 |
| ② `RISK_GAIN_K 1.7 → 2.4` | 只放大正向属性（MONEY/FAME/INT/HP） | **不升 STRESS** ✅ | 正确 |
| ② `RISK_LOSS_K 1.35 → 1.15` | 只缩小**非 STRESS** 的负面冲击 | **不升 STRESS** ✅ | 正确 |
| ② `RISK_STRESS_ADD = 4` | **保持不变** | ⚠️ **中性——不降** | 见下 |
| ③ `RELAX_ACTS −10 ~ −16` | 新增 | **降** ✅ | 正确 |
| 自住房 `STRESS −3/年` | 新增（依赖房价取向） | **降** ✅ | 正确 |
| `socialAct` 朋友 `−3 → −1` | 降幅变小 | ⚠️ **相对升 +2** | 仅为去重叠，量级极小，可接受 |

**→ 没有任何一处把 STRESS 往上推。方向确认无误。**

#### ⚠️ 但核出一条机制错误：② **不改变** STRESS 流入 `I`

`RISK_STRESS_ADD = +4` 是**在 `scaleEff` 之外覆盖赋值**的（这正是本 Spec §2.② 参数表里我自己强调的），而 `scaleEff` 只被 `eventChoices()` 的 risk3 使用（engine.js:1012），且 STRESS 不走它。

> → **`RISK_LOSS_K 1.35 → 1.15` 只降低 HP / MONEY / MOOD 的负面冲击，对 STRESS 流入 `I` 的影响精确等于 0。**

**因此 §3 那句「② 的作用就是把 `I` 从 ~40 压到 ~35」是错的。** ② 的真实作用是「让激进流不那么快把 HP 和钱耗光」，**不是降压力**。

**后果（这是 S-1/S-2 的真实风险）**：
```
S* = (I − 22) / 0.12
若激进流 I = 40（② 压不下来）→ S* = 150 > 120 ❌ → 激进流仍然会死 → S-1 / S-2 判 FAIL
```

#### 方案 A 的否决（team-lead，2026-S1）

> **`K 0.12 → 0.20` 治的是尾巴，削的是全身。**
> `I=28`（进取流）的 `S*` 会从 50 掉到 30 —— **正常玩家的压力系统被削掉 40%**。「用一个全局参数去修一个局部失控，是拿系统的整体表现换一个指标。」
> **方案 A、B 均不采纳。** 方案 C 的一半（先测 `I` 再定恢复参数）**采纳**。

#### ✅ 方案 D（team-lead 提出，我复核并定稿）：**分段恢复 —— 阈值以下逐点不变，只压失控尾巴**

```js
// engine.js:1484  yearBase()
// 方案 D 定稿形式
const over = Math.max(0, s.STRESS - STRESS_DAMP_T);
s.STRESS = Math.max(0, s.STRESS - (STRESS_RECOVER_FLAT
                                 + s.STRESS * STRESS_RECOVER_K
                                 + over * STRESS_DAMP_Q));
```

| 参数 | 值 | 状态 |
|---|---|---|
| `STRESS_RECOVER_FLAT` | `7` | ✅ 定稿 |
| `STRESS_RECOVER_K` | `0.12` | ✅ **定稿为 0.12，不再改动**（方案 A 已否决） |
| `STRESS_DAMP_T`（阈值） | **`70`** | ✅ **定稿**（理由见下） |
| `STRESS_DAMP_Q`（阻尼系数） | `clamp((I_P75 − 34)/30, 0, 0.35)`；**暂定 `0.25`** | ⏳ **等 quality-lead 实测 `I` 后覆盖** |

**为什么阈值定在 70（我复核后确认 team-lead 的初值是对的）：**
1. **它必须高于「正常玩家的最高稳态」**。用满减压 + 自住房时，`I = 30.4` 对应 `S* = 70`；保守流（12）/ 稳健流（20）/ 进取流（28 → `S* = 50`）全在阈值以下 → **逐点不变** ✅
2. **它落在既有的「红区」语义里**。`yearBase` 用 `STRESS < 55` 判定 HP 增减（age ≤ 35 档）；**70 = 55 之上再 15 点**，即「身体已经在掉血、但还没撞上限」的那一段 —— 语义上正是「人开始本能地找出口」的区间。
3. 距 120 上限还有 50 点，**给阻尼留出足够的作用空间**。

**函数形式：保留分段线性（hinge），不用 `S²` 平滑项。**
理由：team-lead 要保住的核心性质是「**阈值以下完全不动**」——**只有 hinge 形式能精确做到**。任何 `S²` / 平滑项都会在阈值以下引入（哪怕很小的）额外恢复，等于部分地犯方案 A 的错。
代价是恢复函数在 `S = 70` 处**斜率不连续**（0.12 → 0.12+q）。**这不会造成病态**：恢复量对 `S` 单调递增 → `S_{t+1} − S_t = I − R(S)` 对 `S` 单调递减 → **不动点唯一且稳定，不会振荡**。

**定稿后的闭式解（工程侧可直接抄）：**

```
记 B = 22（= 7 固定恢复 + 12 减压行动 + 3 自住房）
若 I ≤ B + K×T = 30.4 ：   S* = (I − 22) / 0.12            ← 与今天逐点相同
若 I >  30.4          ：   S* = (I − 22 + q×T) / (0.12 + q)
                              = (I − 4.5) / 0.37   （q = 0.25 时）
```

| `I` | 玩家画像 | 现状 `K=0.12` 单段 | **方案 D（q=0.25）** | 方案 A（已否决） |
|---|---|---|---|---|
| 12 | 保守流 | 0 | **0（不变）** ✅ | 0 |
| 20 | 稳健流 | 0 | **0（不变）** ✅ | 0 |
| 28 | 进取流 | 50 | **50（不变）** ✅ | 30 ⬇ |
| 30.4 | 边界 | 70 | **70（不变）** ✅ | 40 |
| 34 | 偏激进 | 100 | **79.7** | 60 |
| 40 | 激进流 | **150** ❌ | **96** ✅ | 90 |
| 50 | 亡命流 | 233 ❌ | **123** 🟡（仍可死——**这是有意的**） | 140 |

**存活上限从 36.4 抬到 48.9**（`S*=120` 对应的 `I`），**而 `I ≤ 30.4` 的玩家体验完全不变** —— 这正是 team-lead 要的「针对失控尾部的阻尼，不是全局削弱」。

**`q` 的拟合公式（实测 `I` 到达后直接代入）：**

```
目标：让 I_P75（激进流 P75 流入）的稳态落在 S* = 100
→    q = (I_P75 − 22 − 0.12×100) / (100 − 70) = (I_P75 − 34) / 30
→    q = clamp(q, 0, 0.35)
```

| 实测 `I_P75` | 拟合 `q` | `S*(I_P75)` | 说明 |
|---|---|---|---|
| ≤ 34 | **0** | ≤ 100 | **不需要任何阻尼**，`K = 0.12` 单段即可 |
| 38 | 0.133 | 100 | |
| **41.5** | **0.25** | **100** | 暂定默认值 |
| 45 | 0.35（触顶） | 101 | |
| ≥ 44.5 | 0.35（封顶） | > 100 | 封顶理由见下 |

**`q ≤ 0.35` 的封顶理由**：`q` 越大，阈值以上 `S*` 对 `I` 越不敏感（`S*` 斜率 = `1/(0.12+q)`）。`q > 0.35` 后**激进流与亡命流的稳态差被压到 < 20 点，玩家画像之间的压力分化消失** —— 那等于在阈值以上重演一次方案 A 的错误。**保留「亡命流仍可能死」是设计意图**，不是缺陷（S-1/S-2 的目标只针对激进流）。

> ⚠️ **在实测 `I` 到达前：`STRESS_RECOVER_K = 0.12` 与 `STRESS_DAMP_T = 70` 可以落；`STRESS_DAMP_Q` 先按 0.25 落一个可回滚的默认值，并在代码注释里写「待 quality-lead 实测 `I_P75` 后按 `(I_P75−34)/30` 覆盖」。**

### 3.1 组合后的稳态（**按方案 D，`q = 0.25`**）

设 `I` = 年 STRESS 流入，玩家使用减压行动且持有自住房：

```
S_{t+1} = S_t + I − [7 + 0.12×S_t + q×max(0, S_t − 70)] − 12 − 3     // q = 0.25

稳态（方案 D 闭式解）：
  I ≤ 30.4  →  S* = (I − 22) / 0.12            ← 与今天逐点相同
  I >  30.4 →  S* = (I − 22 + 70q) / (0.12 + q) = (I − 4.5) / 0.37
```

| `I` | 玩家画像 | 现状（无稳态，撞顶年限） | **方案 D `S*`** | 判定 |
|---|---|---|---|---|
| 12 | 保守流 | 120（约 25 年撞顶） | **0** | ✅ 健康 |
| 20 | 稳健流 | 120（约 9.2 年） | **0** | ✅ 健康 |
| 28 | 进取流 | 120（约 5.4 年） | **50** | ✅ 健康（**与今天逐点相同**） |
| 30.4 | 阻尼边界 | — | **70** | ✅ 阈值 |
| 35 | 偏激进 | 120（约 4.3 年） | **82.4** | ✅ 高压但可活 |
| 40 | 激进流 | 120（约 3.7 年） | **96** | ✅ 可活（原 150 ❌） |
| 50 | 亡命流 | 120（约 3 年） | **123** 🟡 | **仍可能死 —— 这是有意保留的画像分化** |

**② 的真实作用（v1.1 更正）**：`RISK_LOSS_K 1.35 → 1.15` 让每次风险选项的**非 STRESS** 负面冲击降 15%（HP / MONEY / MOOD），配合 `RISK_GAIN_K 2.4` 让正面收益足以修复 HP/MOOD —— **它救的是「耗不起」，不是「压力大」**。降 STRESS 只能靠 ① 与 ③（见 §3.0）。

**结论（v1.2，按方案 D `q = 0.25`）**：三条齐上 → **激进流 `S* ≈ 96`（原 150），落在 120 上限内** → 平均寿命可达 60+，熄灭率 ≤25%。
**且 `I ≤ 30.4` 的所有玩家（保守 / 稳健 / 进取）稳态与今天逐点相同**，压力系统的张力被完整保留。

> ⚠️ **以上按 `q = 0.25` 推演。实测 `I_P75` 到达后按 `q = clamp((I_P75−34)/30, 0, 0.35)` 覆盖此表；若 `I_P75 ≤ 34`，则 `q = 0`，不需要任何阻尼。**

## 3.7 画像分化定稿 · 熄灭率目标与校准流程（**v1.3**）

### 3.7.1 ✅ 熄灭率目标（**定稿**）

| 画像 | 熄灭率目标 | 存活率 | 梯度 |
|---|---|---|---|
| 稳健 / 保守 | **≤ 0.10** | 0.90 | — |
| 激进流 | **≤ 0.25**（既有 S-2） | 0.75 | −0.15 |
| **亡命流** | **≤ 0.40** | 0.60 | −0.15 |

**采纳 team-lead 的 0.40，并补一条定义无关的内容可达性门 S-2b**（亡命流「活到 ≥76 岁」比例 ≥ 0.50）。理由：
- **梯度是等差的**（存活率 0.90 / 0.75 / 0.60，每档 −0.15）。这个梯度可直接讲给玩家听：「每上一个风险档，多付 15 个百分点的早亡率」，也让 QA 一眼能看出哪个档位跑偏。
- **0.40 满足 team-lead 的原则 2**：60% 的亡命流玩家能活过中年。若定 0.25，亡命与激进**无分化**，「亡命」这个玩法就没有代价，画像系统失去意义（原则 1）。
- **但 0.40 有一个定义依赖**：若「熄灭率」= 活不到 60 岁，那么 60% 的幸存者还要再过一关（60→76）才能看到晚年内容，实际看到晚年的比例会低于 60%。**S-2b 就是为消除这个歧义而设** —— 它直接量「看到晚年内容的比例」，与熄灭率怎么定义无关。**两者冲突时以 S-2b 为准。**

> ⚠️ **请 team-lead / quality-lead 统一「熄灭率」的定义**（活不到 60？活不到 76？还是非自然死亡？）。三种定义下 0.40 的含义差别很大。S-2b 不依赖定义，可先落。

### 3.7.2 ⚠️ 分化不能只押在熄灭率上（**我补的两条非死亡维度**）

**单一全局参数 `q` 只能命中一个目标** —— 三个画像的熄灭率都由同一个 `q` 单调决定，无法独立调。所以：

- **驱动目标 = 激进流 ≤ 0.25**（既有门，且是质量侧两画像共用的严门）；
- **亡命流 ≤ 0.40 是校验门，不是调参目标。**

若出现「激进已达标但亡命 > 0.40」，说明两画像的 `I` 分布过于接近 —— **此时不得靠继续升 `q` 解决**（那会把激进压到 < 0.10，分化消失，正是我自己在封顶理由里担心的）。应改用非 `q` 手段。

**因此分化必须同时在非死亡维度上体现（新增两条验收）：**

| 门 | 指标 | 意图 |
|---|---|---|
| **S-8** | **寿命中位数：激进 ≥ 60、亡命 ≥ 50** | 亡命流「活得更短」但不「活不到中年」——分化落在寿命而非生死 |
| **S-9** | **终局净资产方差：亡命 > 激进 × 1.5** | 亡命流的分化感主要应由**高方差**承担（要么暴富、要么潦倒），而不是由死亡率承担。这也符合「人生模拟器」的核心乐趣 |

> 这两条让「亡命」这个玩法即使熄灭率被压到接近激进，**代价依然真实存在** —— 这才是分化该待的地方。

### 3.7.3 拟合改用 `I_P75`，闭式解只作初值（**采纳 team-lead**）

**P90 会系统性过阻尼**：用 P90 拟合等于要求 90% 存活，熄灭率会被压到 ~0.10，**亡命流被一起压平，分化在拟合阶段就消失**。

```
q₀ = (I_P75 − 22 − 0.12 × 100) / (100 − 70) = (I_P75 − 34) / 30
q₀ = clamp(q₀, 0, 0.35)
```

（`I_P75` 对应「75% 存活」= 熄灭率 0.25，与 S-2 门限同一个分位点。）

### 3.7.4 校准规则（**不是试错，是二分**）

`q ↑ → 恢复更强 → 熄灭率 ↓`，**单调**。所以可以二分收敛，不需要盲目迭代：

```
轮 1：q = q₀（P75 拟合初值），实测三画像熄灭率 + S-2b 的内容可达比例
轮 2：
  若 亡命熄灭 > 0.40            → q += 0.05
  若 亡命内容可达 < 0.50        → q += 0.05   ← S-2b 优先于 S-2a
  若 激进熄灭 > 0.25            → q += 0.05   ← 这是驱动门
  若 亡命熄灭 < 0.30 且 (亡命 − 激进) < 0.10 → q −= 0.05  ← 分化不足，放阻尼
  若 稳健熄灭 > 0.10            → 停止调 q，单独排查
                                  （稳健流 I 极低，不该受阻尼影响；它超标说明
                                    死因不是 STRESS 越线，而是 HP / 疾病 / 意外）
收敛判据：三画像同时满足 S-2 / S-2a / S-2b，且 (亡命 − 激进) ≥ 0.10
```

**允许 2 轮迭代**（team-lead 已同意）。依据是本项目已出现三次「推演 vs 实测」的系统性偏差（D-1、A-08、39.2 年），一次定稿的预期不现实 —— **我接受这个前提，不再声称闭式解可以直接定稿。**
