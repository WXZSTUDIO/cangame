## 0. 一句话结论

quality-lead 的 5 条建议**方向全对、量级需重排**：5 条我全部「修订后接受」，没有一条原样接受，也没有一条拒绝。原因是 5 条建议如果同时按原值落地，会与「现金通胀」形成 **6 重叠加削减**，把「投资」从当前的主导策略直接打成**反向主导策略（谁都不投资）**——那是比现在更糟的失败态。本 Spec 把 5 个旋钮**分工到 5 个互不重叠的作用面**（上限 / 囤积 / 斜率 / 机会 / 周转），每个旋钮只承担一部分削减任务。

## 1. 根因回顾（本 Spec 的推演地基）

### 1.1 四套互不相容的价格尺度

| 受年代缩放影响 | 缩放表 | 1985→2025 倍数 |
|---|---|---|
| 房价 | `HOUSE_INDEX` | ×6.9 |
| 家庭收入 / 家庭资产 / 医疗 / 彩票 / 贷款 / 家庭账簿 | `FIN_SCALE` | ×4.2 |
| **职业年薪与支出** | **无（×1.0）** | ×1.0 |
| 教育 / 养育支出 | **无（×1.0）** | ×1.0 |

`careerIncome()`（career.js:483-491）**完全没有 `FIN_SCALE(year)`**——这是「劳动收入在经济里失声」的结构性根源。

### 1.2 三大放大器

1. **一次性机会高倍回报**：`INVESTMENTS` 的 `base` 即持有期总倍率，`inv_btc = 8.0`。但真正的杀伤力在**年化**：`inv_imf_usd = base 2.6 / hold 2` → 年化 **61.2%**；`inv_imf_junk = 4.2 / hold 3` → 年化 **61.3%**。
2. **`FIN_SCALE` 双吃年代差**：同一张表同时作用于**投入端**（cost）与**回报端**（结算额），年代越晚，玩家用「更贵的本金」换「更贵的回报」，而工资不动。
3. **零摩擦 / 零税费 / 现金零通胀**：现金天然是最优避险资产，早期攒钱 > 一切。

### 1.3 A-07 隐藏乘子（**前置依赖，未落地则本 Spec 无法校准**）

`careerIncome()` 实测值比阶梯表高 **2.34×–3.7×**，乘子来自：资历 `0.028/年`、`(1+INT/520)`、`(1+NET/1000)`、`(1+LOY/1100)`、`salaryK`、学历——**均不在任何配置表内**。

> ⚠️ **硬依赖**：本 Spec 中一切以「收入」为分母的指标（封顶基数、房价收入比、工资占净资产比）都必须用 **A-07 修复后的 `careerIncome()` 真值**校准。README 的依赖顺序 `A-07 → S-02 → S-03 → B-04` 不可倒序。**建议 engineering-lead 先落 A-07（把乘子显式化进 `CAREER_META`），再落本 Spec。**

## 2. 五条建议逐条裁决

### ① 单年资产性收益封顶 `min(gain, careerIncome(state) × 3)`

#### 裁决：**修订后接受**

#### 原样接受的问题
- `careerIncome()` 在**大学生 / 失业 / 退休 / 待业**状态下趋近 0 → 封顶退化为 **0**，退休后靠资产收益养老的合法玩法被直接判死。这恰好是 A-01「晚年真空」的经济侧成因之一，会与本次 Sprint 的晚年内容包自相矛盾。
- A-07 未落地前，`careerIncome()` 真值未知，×3 的绝对量级无法校准。
- 若本金极小（如 500 万），封顶不起作用；若本金极大，封顶过严，会与「流动门：骑手 vs AI 终局差距 50–150×」直接冲突。

#### 修订方案

```
// 1) 封顶基数：给收入参考值一个地板，避免退休/失业年归零
incomeRef(s) = max(
  careerIncome(s),                    // A-07 修复后的真值
  livingCost(s) * 2,                  // 生活成本随家庭/资产上升，随年代自动抬升
  INCOME_FLOOR                        // 常量地板
)

// 2) 封顶值
capGain = incomeRef(s) * GAIN_CAP_K

// 3) 只作用于「当年资本利得净额」，不作用于工资/继承/事件一次性收入
netCapGain(s) = min(netCapitalGainThisYear, capGain)
```

| 参数 | 建议值（内部量级） | 说明 |
|---|---|---|
| `GAIN_CAP_K` | `3.0` | 保留 quality-lead 的 ×3 口径 |
| `INCOME_FLOOR` | `6,000,000` | ≈3.3 万 RMB/年。退休后仍允许每年最多约 1,800 万内部（≈10 万 RMB）的资产收益：够体面养老，不足以失控 |

#### 边缘豁免（必须实现，否则会误伤）
- **小额本金豁免**：若年初可投资资产 `A < 20,000,000`（≈111 万 RMB），封顶值取 `max(capGain, A * 0.5)`。目的：保护「小钱起步」玩家的复利体验（SDT 胜任感当前仅 3/10，不能再削）。
- **豁免对象**：继承所得、事件一次性收入（如 `b01` 的 `MONEY: 500000000` 融资）、工资结余——**不进入封顶核算**。

#### 验收挂钩
对应**劳动门**：工资结余 / 终局净资产 **≥ 35%**。

### ② 现金每年 `-CPI`

#### 裁决：**修订后接受**

#### 原样接受的问题
quality-lead 建议「CPI 表 = FIN_SCALE 增速（1985–2025 年化 3.65%）」。但 `FIN_SCALE` 在本作里**同时是家庭收入缩放表**。若 CPI 完全等于 FIN_SCALE：
- 家庭收入与支出同步缩放 → 对家庭账簿净效应为 0；
- 而 `careerIncome()` **完全不缩放** → 对玩家个人现金是**纯扣血**，且扣的是「发展红利」而非「通胀」。
等于用一个数字同时表达两件不同的事，改了等于白改，还会引入新的不一致。

#### 修订方案：独立 `CPI_INDEX` + 应急金盾

```
// market.js 新增
const CPI_INDEX = [ [1985,1.0], [1995,1.32], [2005,1.74], [2015,2.30], [2025,2.80], [2040,4.10], [2060,6.10] ];
const CPI_ANNUAL = 0.026;        // 年化 2.6%（低于 FIN_SCALE 的 3.65%）
const CASH_SHIELD = 30000000;    // ≈16.7 万 RMB 应急金，免通胀

// 每年结算（只对现金/存款，不对已投资产）
const shield = CASH_SHIELD * tableAt(CPI_INDEX, year);
s.MONEY -= Math.max(0, s.MONEY - shield) * CPI_ANNUAL;
```

| 参数 | 建议值 | 理由 |
|---|---|---|
| `CPI_ANNUAL` | `0.026` | 取 FIN_SCALE(3.65%) 的 ~71%。让**名义收入涨得比物价快** = 真实的「发展红利」被建模出来，同时现金仍有持有成本 |
| `CASH_SHIELD` | `30,000,000`（随 CPI 上调） | 保护早期/稳健流玩家的应急金。缺失此项会把「稳健流」打成新的劣势流，与「区分门 S ≤35%、标准差 ≥12」冲突 |
| 作用面 | **仅现金与存款** | 股票/房产定价已在名义空间（`growth`、`HOUSE_INDEX` 均含通胀），再扣一次是双重计价 |

#### 设计意图
现金从「最优避险资产」降级为「应急工具」，但仍保留其**流动性价值**（可随时应对医疗/教育/机会事件）。这是「有成本但不惩罚」的取态。

### ③ 股票阻尼 `0.75 → 0.55` 且单标的年化 clamp 8%

#### 裁决：**修订后接受**（阻尼取 **0.62**，clamp 改为**漂移上限 + 波动同步约束**）

#### 现状实测（`marketTick`：`k = growth × growthDamp + shock + gauss() × vol`）

| 标的 | `growth` | ×0.75（现状） | ×0.62（建议） | ×0.55（quality-lead） |
|---|---|---|---|---|
| 沪深 300 ETF `s_kospi` | 0.068 | 5.10% | **4.22%** | 3.74% |
| 华兴半导体 `s_hansung` | 0.102 | 7.65% | **6.32%** | 5.61% |
| 智源 AI `s_ai` | 0.14 | 10.50% | **8.68% → clamp 8%** | 7.70% |
| 星光娱乐 `s_arirang` | 0.125 | 9.38% | **7.75%** | 6.88% |
| 绿能电池 `s_green` | 0.115 | 8.63% | **7.13%** | 6.33% |
| 比特币 `g_coin` | 0.34 | 25.50% | **21.08% → clamp 8%** | 18.70% |

#### 为什么是 0.62 而不是 0.55

0.55 会让沪深 300 税后（叠加 ⑤ 的 0.5% 双边摩擦 + 15% CGT）落到 **≈2.3%**，而现金在盾内是 0%、盾外是 −2.6%——**风险溢价仅剩约 4.9pt**。再叠加 ① 封顶、④ 年化预算、⑤ 税费，会形成**反向主导策略：干脆不投资**。那会废掉「前世记忆」这一最独特的设计支柱（fun-assessment 里 Mechanics 8/10 的主要来源）。

取 **0.62** 的锚点：沪深 300 税后 ≈ **3.2%**，相对现金 −2.6% 的风险溢价 **≈5.8pt**，与 A 股长期风险溢价（5–6pt）的中国口径对齐。阻尼只承担 5 个削减旋钮中的 **20%** 任务量。

#### 为什么 clamp 必须改口径

`k = growth × damp + shock + gauss() × vol`，`gauss() ∈ [−1, 1]`。若对**含随机项的 `k`** 做 +8% 上限：
- 比特币 `vol = 0.65`（`g_coin`）→ 单年 `k ∈ [−45%, +85%]`，clamp 后**上行全被砍、下行全保留** → 几何年化变成 −13%/年，成为一个**隐形数学陷阱**（玩家看文案以为是「高风险高回报」，实为「高波动必亏」）。这属于设计红线里的**认知过载 / 隐性惩罚**。
- 更糟的是：2008 / 2020 的暴跌叙事会被数值系统打脸（e2008 / x_e02 / x_e03 的文案讲「暴跌」，若下行也被 clamp 到 −8%，叙事与数值直接矛盾，是 BUG 级不一致）。

#### 修订方案

```
// marketTick 内
let drift = s.growth * MARKET_META.growthDamp + (shock || 0);
if (!s.noCap) {
  drift = Math.min(drift, MARKET_META.driftCap);          // 上界 8%
  if (drift < s.growth * MARKET_META.growthDamp) {         // 被 clamp 的标的同步降波动
    volEff = Math.min(s.vol, MARKET_META.volCapWhenClamped);
  }
}
let k = drift + gauss() * volEff;                          // 下界不设限
p = Math.round(Math.max(p * 0.22, p * (1 + k)));
```

| 参数 | 建议值 | 说明 |
|---|---|---|
| `growthDamp` | `0.75 → 0.62` | 见上表 |
| `driftCap` | `0.08` | 只作用于**漂移项**，不含随机项 |
| `volCapWhenClamped` | `0.28` | 被 clamp 的标的波动同步压到 ≤28%，避免负几何收益陷阱 |
| 下界 | **不设限** | 保留崩盘戏剧性，与 e2008 / x_e02 / x_e03 叙事一致 |
| 豁免 `noCap` | `s_kospi`（指数）、存款类 | 稳健标的可预期性是「稳健流」的立身之本 |

### ④ 高倍机会 `×8 → ×3.5`

#### 裁决：**修订后接受**（不是单一 3.5，而是**按「年化预算」重排全部 11 条**）

#### 关键认知修正
问题**不是** `base` 的绝对大小，而是 **年化**：`annual = base^(1/hold) − 1`。当前最夸张的两条不是 BTC，而是 `inv_imf_usd`（2.6 / hold 2 → **61.2%**）与 `inv_imf_junk`（4.2 / hold 3 → **61.3%**）。BTC 的 8.0 / hold 4 = 68.2%，确实最高但只比它们高 7pt。若只把 BTC 降到 3.5，IMF 双雄仍是 61%，经济不会好转。

### ⑤ 0.5% 手续费 + 20% 资本利得税

#### 裁决：**修订后接受**（手续费是**替换**不是叠加；CGT `20% → 15%` + 年度免征额 + 自住房免征）

#### 原样接受的问题
`market.js:8` 现有 `stockFee = 0.0035`（0.35%，买卖双向）。若「0.5% 手续费」是在此之外**新增**，总摩擦 = 0.85%/单边 = **1.7%/轮**。INVESTMENTS 的 `hold` 只有 2–5 年（即 2–5 轮周转），三重摩擦（手续费 + CGT + ①封顶）会把短线机会打穿——而「前世记忆 / 抓住时代机会」是本作最独特的卖点（fun-assessment Mechanics 8/10 的主要来源），不能削死。

#### 修订方案

```js
const MARKET_META = {
  stockFee: 0.005,          // 0.0035 → 0.005（「0.5% 手续费」的正确落法是替换，不是叠加）
  propTax: 0.035,           // 保持不变
  capitalGainsTax: 0.15,    // 新增：资本利得税（quality-lead 建议 20% → 修订 15%）
  cgtAllowance: 5000000,    // 新增：年度免征额（≈2.8 万 RMB）
  cgtExemptSelfLive: true,  // 新增：自住房出售免征（对应「满五唯一」）
  minAge: 20,
  growthDamp: 0.62,
  driftCap: 0.08,
  volCapWhenClamped: 0.28
};
```

| 参数 | 建议值 | 理由 |
|---|---|---|
| `stockFee` | `0.0035 → 0.005` | 替换式上调到 quality-lead 要求的 0.5% |
| `propTax` | `0.035` 不变 | B-04（房价劣选择）**尚未修复**。此时加重房产税负会让买房更劣，与本次 Sprint 的房价取向决策直接打架 |
| `capitalGainsTax` | `0.15`（非 0.20） | ① 中国语境下个人二级市场差价所得实际税负远低于 20%，20% 更像美/韩口径；② 与 ①封顶、②CPI、③阻尼、④年化预算四重叠加后，20% 会压出反向主导策略；③ 15% 已足够制造周转痛感 |
| `cgtAllowance` | `5,000,000` | 小额交易不被税吃掉，保护早期玩家与稳健流 |
| `cgtExemptSelfLive` | `true` | 支持 `housing-decision.md` 方案②（自住房 = 生活选择而非投机），且符合中国「满五唯一」语境 |
| 征收时点 | **仅已实现**（`sellStock` / `sellProp` 的净利） | 不溯及浮动盈亏，避免玩家「账面赚钱却要交税」的挫败 |

## 4. 修复后的合理区间目标（供 8 道回归门校准）

> 口径说明：金额**以内部单位为主**，括号内为 `÷180` 后的人民币近似值。若 `balance-analysis.md` 中的门限原为人民币口径，请以 quality-lead 复核结果为准——我在文中同时给出两种口径以避免误读。

| 指标 | 目标区间（内部单位） | ≈ RMB（÷180） | 对应回归门 |
|---|---|---|---|
| **房价收入比**（首套购房时的 `housePrice / careerIncome`） | **6 – 15×** | — | 买房门 |
| **工资结余 / 终局净资产** | **≥ 35%** | — | 劳动门 |
| **终局净资产 P10** | 500 万 – 1,500 万 | 2.8 万 – 8.3 万 | 通胀门 |
| **终局净资产 中位数** | **2,000 万 – 2 亿** | 11 万 – 111 万 | 通胀门 |
| **终局净资产 P90** | 8 亿 – 15 亿 | 444 万 – 833 万 | 通胀门 |
| **稳健流买房率** | 55% – 85% | — | 买房门 |
| **首次购房年龄** | 30 – 38 岁 | — | 买房门 |
| **换职业率** | 25% – 35% | — | 流动门 |
| **骑手流 vs AI 流终局净资产差距** | 50 – 150× | — | 流动门 |

| **稳健流 S 级结局占比** | ≤ 35% | — | 区分门 |
| **结局评分标准差** | ≥ 12 | — | 区分门 |
| **1000 局连跑崩溃数** | 0 | — | 稳定门 |

### 4.1 推演：为什么这组参数能命中

1. **通胀门**：① 封顶把「钱生钱」的相对斜率锁在收入的 3 倍以内 → 终局净资产的主要贡献者从「复利」变回「职业 + 机会」，中位自然落到 2,000 万–2 亿区间。② CPI 削掉囤现金的尾部 → P90 不再由「早期攒钱 + 零通胀」拉到 15 亿以上。
2. **劳动门**：`GAIN_CAP_K = 3` 直接规定「资产收益 ≤ 3 倍年收入」，等价于「劳动收入在净资产里至少保留一席」，配合 ⑤ 税收降低资产净回报，≥35% 可达。
3. **流动门**：② + ⑤ 让「不投资」不再是免费午餐；③+④ 让「投得早、投得准」仍有 25%–37% 的年化 → 骑手流（无本金、无信息）与 AI 流（有本金、有前世记忆）的差距得以维持在 50–150×。
4. **区分门**：② 的 `CASH_SHIELD` 与 ⑤ 的 `cgtAllowance` 保护小额玩家的下限；① 的小额本金豁免避免「稳健流无路可走」。两端同时收敛 → 标准差下降，但 S 级仍靠机会事件拉开 → 标准差 ≥12 可保。

## 5. 边缘情况（≥3 类，必列）

| # | 场景 | 现状风险 | 处理 |
|---|---|---|---|
| E-1 | **退休 / 失业年** `careerIncome() ≈ 0` | 封顶退化为 0，资产收益被全砍 | `INCOME_FLOOR = 6,000,000` + `livingCost × 2` 地板 |
| E-2 | **大学生 / 未成年**（age < 20） | 无市场行为，但继承/赠与会入账 | 封顶只对**资本利得**生效，继承与事件收入豁免 |
| E-3 | **年初资产 < 2,000 万** | 封顶形同虚设，且小额玩家失去复利体验 | 小额本金豁免 `max(capGain, A × 0.5)` |
| E-4 | **危机年暴跌**（2008 / 2020，shock 为负） | 若下界也 clamp，与 e2008/x_e02/x_e03 的「暴跌」文案矛盾 | 下界**不设限**，`driftCap` 只管上行 |
| E-5 | **被 clamp 的高波动标的**（BTC `vol 0.65`） | 低漂移 + 高波动 = 负几何收益，隐形陷阱 | `volCapWhenClamped = 0.28` 同步降波 |
| E-6 | **现金为负（负债）** | `Math.max(0, MONEY - shield)` 对负值返回 0，需确认不会误加钱 | 明确：`MONEY` 为负时**不扣也不补**，负债利息另由贷款系统处理 |
| E-7 | **同一年内多次买卖** | 封顶按「净额」还是「逐笔」？ | 按**当年净额**累计（年末统一裁剪），避免高频交易被逐笔削；但手续费仍逐笔收（周转成本在 ⑤，不在 ①） |
| E-8 | **自住房 + 投资房并存** | `own_house` 已存在，但无「自住 / 出租」区分 | 需新增 `ref.selfLive` 标记（`housing-decision.md` 方案②依赖），CGT 免征据此判定 |
| E-9 | **老存档加载** | 新字段缺失 | `migrateState()` 补默认值：`MONEY` 不变、`CPI_INDEX` 按当前年计算、无历史补扣 |
