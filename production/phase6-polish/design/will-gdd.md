## 1. 概述

### 1.1 这个系统是什么

玩家在**生前**主动立下一份遗嘱，决定自己死后净资产如何在**配偶 / 子女 / 慈善**之间分配，并在立嘱的当下**立即**承受情感与关系后果——而不是等死后再结算。

### 1.2 为什么现在做（与 Phase 6 诊断的对齐）

| 诊断 | 遗嘱系统的修复作用 |
|---|---|
| **A-01 晚年真空**（66+ 空转 47–56%） | 遗嘱是 70+ 阶段**唯一一个完全由玩家主导**的高权重决策点，天然填补晚年空转 |
| **SDT 自主感 7 / 胜任感 3 / 关联感 8** | 遗嘱是**关联感的终极表达**：你这一生最后一句话说给谁听。同时它是可规划的（胜任感 +） |
| **Dynamics 4/10** | 遗嘱让「晚年」第一次有分歧：偏心长子还是均分？捐掉还是留给孩子？——**没有标准答案** |
| **S4 子孙继承（远期）** | 遗嘱是 S4 的**唯一入口**：谁继承多少，决定下一局主角从哪里起步 |

### 1.3 设计支柱对齐

| 支柱 | 本系统如何服务 |
|---|---|
| ①「一代人的命运切片」 | 遗嘱的分配理由文案按**年代**生成（1980 年代的「房子留给长子」vs 2020 年代的「平分，别为了钱伤感情」） |
| ②「选择没有标准答案」 | 四种模式**各有真实代价**，无主导策略（见 §4.4 验证） |
| ③「数字背后是人生」 | 每一项分配都挂具体的**物件**（房子 / 那块表 / 一本存折），不是抽象的百分比 |

### 1.4 范围分层

| 层级 | 内容 |
|---|---|
| **MVP** | 70+ 立嘱入口 + 4 种分配模式 + 子女亲密度反馈 + 死亡时执行 |
| **目标** | 病重事件触发 + 年代化文案 + 指定标的归属（房子/传家物）+ 修改遗嘱 |
| **愿景** | 遗嘱执行后的**后代视角回放**（S4 子孙继承的前置演出） |

## 2. 核心机制

### 2.1 立遗嘱的时机（三个入口）

| 入口 | 触发条件 | 优先级 | 说明 |
|---|---|---|---|
| **A. 主动入口** | `age ≥ 70`，「生活」页出现「立一份遗嘱」按钮 | 中 | 玩家自主发起，**每年可修改 1 次** |
| **B. 事件触发** | `o04`（age 70–80「医生说了那个词」）、`x_o07`（age 62–80 手术抉择）、`w_teeth`（age 80–98 体检报告，**本 Sprint 新增**）触发后，次年 `queue.unshift` 一条 `will_prompt_<age>` 事件 | 高 | 借势，不打断叙事 |
| **C. 强制触发** | `age ≥ 65 且 HP < 30` | 最高 | 不给拒绝选项，避免玩家暴毙后无遗嘱 |

> **不设 70 岁以下入口**：年轻人立遗嘱在本作语境里既不符合现实频率，也会稀释系统的情感重量。

### 2.2 四种分配模式

| 模式 | id | 一句话 | 可得者 |
|---|---|---|---|
| **均分** | `equal` | 「别为了钱伤了感情。」 | 所有存活子女等分 |
| **偏心** | `bias` | 「那一个，欠他/她的最多。」 | 指定 1 名子女拿大头，其余均分剩余 |
| **慈善** | `charity` | 「他们自己会活。」 | 全部捐出（对应 `x_o06` / `o03` 的基金叙事） |
| **给配偶** | `spouse` | 「先给他/她养老。」 | 配偶全额 |

### 2.3 执行时点

```
立遗嘱（生前，立即结算情感与关系）
      ↓
  可修改（每年 1 次，仅限 A 入口）
      ↓
玩家死亡 → 执行分配（executed = true）
      ↓
  写入 state.will.distribution 快照
      ↓
  S4 预留：heirLine.carryAssets = 指定继承人所得
```

### 2.4 与现有 `inherit_at_` 继承事件的关系（关键）

> ⚠️ **这两件事方向相反，但极易混淆，必须明确区分。**

| 维度 | `inherit_at_<age>`（现有） | `will_at_<age>`（本系统） |
|---|---|---|
| 玩家角色 | **继承人**（儿女） | **被继承人**（父母） |
| 资金方向 | **入账**（父母的遗产进来） | **出账**（自己的钱出去） |
| 触发 | `parentTick`：双亲均不在且 `age ≥ 19`，`queue.unshift` 插队 | 70+ 主动 / 病重事件 / 强制 |
| 选项 | 全额 / 限定 / 放弃 | 均分 / 偏心 / 慈善 / 配偶 |
| flag 前缀 | `inherit_*` | `will_*` |

**三条硬性接缝规则**：

1. **id 命名必须区分**：遗嘱事件用 `will_at_<age>` / `will_prompt_<age>`，绝不可复用 `inherit_at_` 前缀，否则 `parentTick` 的判断逻辑会误伤。
2. **同年冲突的优先级**：若某年同时发生「继承父母遗产」与「本人死亡执行遗嘱」，**先入账后出账**——`inherit_at_` 在年初执行，`will` 在死亡结算时执行。
3. **flag 互不干扰**：`inherit_full` / `inherit_limited` / `inherit_none` 与本系统的 `will_equal` / `will_bias` / `will_charity` / `will_spouse` 完全独立，任何逻辑不得交叉读取。

### 2.5 对子女关系值的反馈（**需新增字段**）

**现状问题**：`state.children[i]` 只有 `{ name, gender, born, alive }`（engine.js:58），**没有任何关系值字段**。本系统必须新增：

```js
state.children[i] = {
  name, gender, born, alive,
  rel:  50,     // NEW 亲密度 0–100，初始 50（出生时）
  gen:  1,      // NEW 世代序号（S4 预留）
  heir: false   // NEW 是否被指定为 S4 接续主角
};
```

> `rel` 的后续用法（本 Sprint 只做写入，不做消费）：`rel` 高 → 晚年事件里孩子来看你（`w_grand_grad` 的权重上调）；`rel` 低 → 触发「孩子今年又没回来」事件。

## 4. 公式

### 4.1 可分配净资产 `E`

```
E = max(0, netWorth(state) − FUNERAL_COST)
netWorth(state) = stats.MONEY + propValue(state) + stockValue(state) − market.debt
```

| 变量 | 单位 | 来源 |
|---|---|---|
| `stats.MONEY` | 内部货币 | `state.stats.MONEY` |
| `propValue` | 内部货币 | `market.js` `propValue(state)` |
| `stockValue` | 内部货币 | `market.js` `stockValue(state)` |
| `market.debt` | 内部货币 | `state.market.debt` |
| `FUNERAL_COST` | 内部货币 | `20,000,000` |

### 4.2 分配计算

设存活子女集合 `K`（`children.filter(c => c.alive)`），`n = K.length`。

| 模式 | 计算 |
|---|---|
| `equal` | `share_i = E / n`，∀i ∈ K |
| `bias` | `share_t = E × biasRatio`（t = `biasTarget`）；`share_i = E × (1 − biasRatio) / (n − 1)`，∀i ∈ K, i ≠ t |
| `charity` | `share_i = 0`，全部捐出 |
| `spouse` | `share_i = 0`，配偶全额 |

**n = 0 时**：`charity` 与 `equal` 均退化为「无人继承」→ 按 `charity` 处理（捐出），并给出专属文案「你翻遍了通讯录，发现没有一个人可以写上去」。

**n = 1 时**：`bias` 不可用（只有一个孩子，偏心无意义）→ 按钮置灰并提示。

### 4.3 慈善 → FAME

```
FAME_gain = clamp( round( sqrt(E / 100,000,000) × CHARITY_FAME_K ), 2, CHARITY_FAME_CAP )
```

| `E` | `FAME_gain` |
|---|---|
| 1 亿（≈56 万 RMB） | 6 |
| 10 亿（≈556 万 RMB） | 19 |
| 100 亿（≈5,556 万 RMB） | 30（封顶） |

### 4.4 子女亲密度反馈公式

设 `r_i = share_i / E`（第 i 个子女实得占比），`n = K.length`：

| 模式 | `Δrel_i` |
|---|---|
| `equal` | `+3`（∀i） |
| `bias`（目标 t） | `+10 + 8 × (r_t − 1/n)` |
| `bias`（其余 i） | `−6 − 10 × (r_t − 1/n)` |
| `charity` | `−6`（∀i） |
| `spouse` | `−8`（∀i） |
| **未立遗嘱（法定继承）** | `−4`（∀i）+ 触发争执事件 |

```
rel_i = clamp(rel_i + Δrel_i, REL_MIN, REL_MAX)
Δrel_i = clamp(Δrel_i, REL_DELTA_MIN, REL_DELTA_MAX)
```

**算例**（`n = 3`，`biasRatio = 0.60`）：

| 角色 | `r` | `Δrel` |
|---|---|---|
| 偏心目标 | 0.60 | `+10 + 8 × (0.60 − 0.333)` = **+12.1 → +12** |
| 其余两人 | 0.20 | `−6 − 10 × 0.267` = **−8.7 → −9**（每人） |

**净亲密度变化**：`+12 − 18 = −6` → 偏心总体上**损害**家庭关系，但把资源集中到一个人身上。这是**真取舍**，不是「偏心更强」。

### 4.5 ⚠️ 主导策略验证（设计红线自检）

| 模式 | 收益 | 代价 | 是否主导？ |
|---|---|---|---|
| `equal` | 全家 `rel +3`、`LOVE+3`、`SEC+5`、`STRESS−6` | 无资源集中，FAME 无 | ❌ 安全（无 FAME 收益，冲 S 级的人不会选） |
| `bias` | 单子女 `rel +12`、`WILL+6` | 其余 −9/人、净 −6、`SEC−4`、`STRESS+8` | ❌ 安全（关系净损） |
| `charity` | `FAME +2~30`、`ETH+12`、`MOOD+5` | 子女 `rel −6/人`、`LOVE−5` | ❌ 安全（与「关联感」支柱对立） |
| `spouse` | `LOVE+7`、`SEC+4` | 子女 `rel −8/人`（最重） | ❌ 安全（代价最重，仅在无子女/配偶在世时理性） |

> **结论：四种模式两两互有胜负，`charity` 是「冲分」路径但毁关系，`equal` 是「关系」路径但无 FAME，`spouse` 是「配偶在世且子女少」的特化解，`bias` 是「单点押注」。无主导策略。** ✅

## 5. 边缘情况

| # | 场景 | 风险 | 处理 |
|---|---|---|---|
| E-1 | **配偶已故时选 `spouse`** | 无人接收，资产蒸发 | 按钮置灰 + 提示「他已经不在了」。若玩家坚持（无其他选项）→ 转为 `charity` 并给专属文案 |
| E-2 | **无子女时选 `equal` / `bias`** | 除零 | `bias` 禁用；`equal` 退化为 `charity`，给「通讯录里没有一个人」文案 |
| E-3 | **全部子女已故**（`alive: false`） | 同上 | 按 E-2 处理 |
| E-4 | **`n = 1` 时选 `bias`** | 偏心无意义 | 按钮置灰 + 提示「就这一个，不用偏」 |
| E-5 | **净资产为负**（负债 > 资产） | `E < 0` | `E = max(0, …)`；`FUNERAL_COST` 仍扣，结果 `E = 0`，遗嘱执行为「什么也没留下」事件 |
| E-6 | **立嘱后资产大幅变动**（卖房 / 破产） | 分配快照失效 | 遗嘱**存的是模式与比例，不是金额**；执行时按当时 `E` 实时计算。避免快照失真 |
| E-7 | **玩家活到 100 岁以上仍未立嘱** | 无遗嘱死亡 | 按「法定继承」处理：所有子女均分，但 `Δrel −4` 且触发「孩子们为了房子吵了一年」事件（`LOVE −5`） |
| E-8 | **同年发生继承 + 死亡** | 资金方向混乱 | 见 §2.4 规则 2：先 `inherit_at_` 入账，后遗嘱出账 |
| E-9 | **修改遗嘱时子女已去世** | `biasTarget` 指向死人 | 修改界面只列 `alive` 子女；若原目标已故，打开界面时强制要求重选 |
| E-10 | **老存档加载** | `state.will` / `children[i].rel` 缺失 | `migrateState()` 补 `will = {made:false, version:1}`、`rel = 50`、`gen = 1`、`heir = false` |
| E-11 | **`biasRatio` 越界** | 分配比例 >1 或 <0 | 钳制到 `[0.50, 0.85]` |
| E-12 | **S4 未开启时写入 `heirLine`** | 无用字段膨胀存档 | `heirLine.enabled = false` 时不写 `carryAssets`；`migrateState` 保证字段存在即可 |
| E-13 | **`w_sell_house`（本 Sprint 新增）已卖房** | 房子不在遗产里 | `items.houseTo` 在 `flags.sold_house` 存在时自动置 `null` 并提示 |

## 6. UI 接口

### 6.1 三个屏幕

| 屏 | 名称 | 内容 |
|---|---|---|
| **S1** | 触发提示 | 卡片式：「你七十岁了。有些话，现在不说，以后就没机会说了。」→ 按钮【立一份遗嘱】【再想想】 |
| **S2** | 分配界面 | ① 净资产概览（`E`，用 `fmtMoney`）② 四种模式卡片（含即时效果预览）③ `bias` 模式下的子女选择器 + 比例滑杆 ④ 标的事项（房子 / 传家物，目标层） |
| **S3** | 确认回执 | 一段**年代化**的遗嘱正文（见 §6.2）+ 【确认】【重写】 |

### 6.2 年代化正文模板（按立嘱年份分支）

| 年代 | 均分模式正文示例 |
|---|---|
| 1985–1999 | 「我这一辈子没攒下什么。剩下的这点，你们三个平分。别因为钱，做不成兄妹。」 |
| 2000–2014 | 「房子留给你妈住到老，剩下的你们平分。谁也别觉得亏。」 |
| 2015–2035 | 「钱平分。那块表给老大——不是因为它值钱，是因为他小时候总拿它玩。」 |
| 2036+ | 「如果你们看到这封信，说明我已经不在了。钱怎么分我都同意，只要你们还来往。」 |

### 6.3 HUD / 关系页联动

- 关系页子女卡片显示 `rel`（0–100）与一句状态文案（`rel ≥ 70`「常常来看你」/ `40–69`「逢年过节会打电话」/ `< 40`「今年还没联系」）。
- 立嘱后，子女卡片追加一行小字：「遗嘱里提到了你」（不透露具体金额，直到玩家死亡）。

### 6.4 无障碍 / 可访问性

- 分配界面的四种模式用**图标 + 文字**双重标识，不依赖颜色区分。
- 比例滑杆提供 **+/− 按钮**替代拖拽（移动端友好）。
- 确认屏的遗嘱正文需可被系统字体缩放（`rem` 单位，不用 `px` 固定）。

## 8. 验收标准

| 门 | 通过条件 |
|---|---|
| W-1 | 70+ 玩家可通过主动入口立嘱；触发率 ≥ 60% |
