## 0. 一句话结论 + 一处前提修正

### 0.1 结论

- **补习不动收益端**（A-08：1600 局正交设计 **6/6 格为正**，方向可签字；我不削、不废除、不设收益衰减）。
- **代价只加在「非收益维度」**：健康、高考压力、倦怠叙事。休闲玩家「刷 3 次」的体验完全不变。
- **收益跳变（D-1）用「档位内连续化 + 补一档」解决**，而不是动 `gaoExamScore` 的权重。
- **专业锁死（D-3）的根因比 team-lead 描述的更严重**：不只是「一本理工偏少」，而是 **`majorOk` 硬门控把「学历越高 → 可应聘职业反而越少」的倒挂也造出来了**。三层修复。

### 0.1b 📌 建模基准声明（A-08 结论已更新，务必按此重读）

> **可签字的（方向）**：补习是**正收益**。1600 局正交设计下，6 个「年龄 × 臂」格**全部为正**——这是唯一稳的结论。
>
> **不可签字的（幅度）**：实测跨度过大，无法精确标定。质量侧独立 harness 复跑两次（800 局 / 1600 局），steady 臂补习主效应分别是 **+58.6% 与 +13.5%**——同一套设计、同一份代码，两次差了 45 个百分点；工程侧三个口径横跨 +25%~+45%。
> → **本 Spec 一律写作「十几到几十个百分点」，不引用任何具体幅度读数。**
>
> **已被证伪的数字**：早期测试侧的「补习 −52.1%」是 **实验装置共线性**造成的混淆（`regression-run.js:370-374` 的 `pn` / `cap` 共线；真实原因是画像差——`explorer` 的 `jobTarget` 为空 → 从不主动应聘 → 落到 `clerk`），**不是补习的效应**。
>
> **本 Spec 全程按「补习 = 正收益」建模。** 全文已核查：**不存在任何「补习有害 / 应削弱 / 应废除」的表述或推论**。具体落点：
> - §4.1 明确「收益端完全不动」——`study +randInt(6,11)`、`INT +randInt(2,4)` 原样保留；
> - §4.2 的三条代价线全部落在 **HP / 高考压力（`cramStress`）/ 倦怠叙事**，不触碰收益端；
> - §4.2 的边际收益表刻意做到「边际从 +1.70 降到 +0.20，**但始终为正**」——补习仍是正收益，只是「刷满」不再是无脑最优；
> - §11 ED-5 要求回归验证「补习 1–3 次玩家与修复前无显著差异」，作为休闲玩家保护闸门。
>
> ⚠️ **本 Spec 的代价参数（`CRAM.*`）全部按 `gaoExamScore` 与 `cramStress` 的机制公式做解析推导，不引用任何模拟幅度读数。** 这正是幅度不可靠时唯一站得住的做法——若后续有人拿某个具体幅度（无论 +13% 还是 +59%）来要求加码或减码，请回到本条。
>
> ⚠️ **第二道闸门（team-lead 已背书）**：**代价只能加在非收益维度**。要调量级就调 `CRAM` 常量，**不要动 `study` / `INT` 增益**。这条同时防「有人拿不可靠幅度来要求加码」。

### 0.2 ⚠️ 一处前提修正（✅ team-lead 已亲自复核源码并确认）

> team-lead 转述的 D-3 表述是「`普通一本` 的专业池**没有一个纯理工**」。
> **这一条不准确。** `MAJOR_LABEL`（engine.js:1821）里 **`'土木工程': '理工'`**，而 `u_yiben` 的专业池（school.js:70）是：
> `['工商管理', '土木工程', '英语', '市场营销', '视觉传达设计', '表演']`
> → 分类结果：**金融 2 / 理工 1（土木工程）/ 师范 1（英语）/ 艺术 2**。
> 也就是说一本**有** 1 个理工专业，只是只有 **1/6**。

这个修正很重要，因为它改变了修复力度：不是「从 0 到 1」的补缺，而是「从 1/6 提到合理占比」的调结构。同时它提醒我们**不要靠肉眼读专业名判断分类**——`土木工程` 看着不像「纯理工」但系统里就是理工；反过来 `环境工程`（二本池）也是理工。

## 2. D-3 · 专业对口锁死（**建议最先修**）

### 2.1 根因不止一层，我拆出三层

**第 1 层：一本/二本的理工供给只有 1/6。** 高薪职业（`programmer` / `hacker` / `ai`）全部 `major: ['理工']`，一本生只有抽到「土木工程」才能进。

**第 2 层（team-lead 未提到，但更严重）：`majorOk` 造出了「学历倒挂」。**
`majorOk` 的开启条件是 `lv >= 3`（本科及以上），而**它同时作用于 `edu ≤ 2` 的低学历职业**。带 `major` 字段的低学历职业有：

| 职业 | `edu` | `major` | 后果 |
|---|---|---|---|
| `nurse` 护士 | **2** | 医学 | **一本 / 211 / 985 生无论什么专业都当不了护士；专科生可以** |
| `clerk` 公司文员 | **2** | 金融 / 师范 | 一本「土木工程 / 英语 / 设计 / 表演」生当不了文员 |
| `sales` 销售 | **1** | 金融 | 同上 |
| `idol` 偶像练习生 | **1** | 艺术 / 体育 | 非艺术类本科生当不了 |
| `streamer` 自媒体 | **2** | 传媒 / 艺术 | 同上 |
| `athlete` 运动员 | **0** | 体育 | 同上 |
| `ecom` 电商运营 | **2** | 金融 / 理工 | 师范 / 艺术类本科生当不了 |

> **学历越高，可应聘的职业反而越少。** 这是纯逻辑 BUG，不是平衡问题，必须最先修。

**第 3 层：`majorOk` 是硬门控（`okFlag = false`），这是 A-03「入错行 ≈ 判无期」的直接成因。** 专业在 18 岁一次性锁定，之后终身不可逆。

### 2.2 处置方案（三层，按成本排序）

#### 修复 A —— 消除学历倒挂（**必做，1 行**）

```js

// 修复：专业对口只约束「本科及以上门槛的职业」
```

## 3. D-1 · 补习收益一次性跳变，之后归零

### 3.1 根因复算

- 211 线 546 → 985 线 616，**空档 70 分 = 10 个 `minScore` 点**。
- 玩家在「刚过 211 线」之后，可用补习预算：从 study 15 到 study 31（实测上限），`Δstudy = 16` → `+3.2` 个 `minScore` 点；附带 `INT` 增益（约 2 次补习 ≈ +6 INT）→ `+2.4` 点。合计 **≈ +5.6 点**。
- **+5.6 < 10（空档宽度）** → 无论怎么刷都够不到 985。
- 而 211 到 985 之间**没有任何档位** → **这 5.6 点的边际收益精确等于 0**。

> 这不是数值问题，是**收益函数不连续**的问题：在两个台阶之间，函数值是常数。

### 3.1b ✅ 独立实证支持（quality-lead 年龄扫描，1600 局正交设计，只读）

上面是从 `gaoExamScore` 机制推出来的；质量侧**独立地**（不依赖本 Spec）做了一张年龄扫描，从数据侧量到了同一件事：

#### 3.2.2 `bestSalaryKFor(gao)` 纯函数抽取（**engineering-lead 已确认可行，v1.3 收录**）

依赖只有 `UNIVERSITIES`（school.js:53）与 `clamp`（engine.js:14），纯数据 + 纯函数，**抽取零障碍**。这是 §3.3 所有门的测量入口。

```js
const SCORE_K = { over: 70, max: 0.10 };
function uniNeed(u) { return Math.round((u.minScore || 0) / 100 * 700); }
function scoreKFor(u, gao) {
  return 1 + clamp(Math.max(0, (gao || 0) - uniNeed(u)) / SCORE_K.over, 0, 1) * SCORE_K.max;
}
function salaryKFor(u, gao) { return u.salaryK * scoreKFor(u, gao); }

/* 纯函数：QA 直接注入整数分直读，绕开 11 年随机过程 */
function bestSalaryKFor(gao) {
  let best = null;
  UNIVERSITIES.forEach(u => {
    if ((gao || 0) < uniNeed(u)) return;      // 够不到
    if (u.id === 'u_fail') return;            // E-12：落榜档不参与连续化
    const k = salaryKFor(u, gao);
    if (!best || k > best.k) best = { uni: u.id, k: k };
  });
  return best;    // { uni, k } 或 null
}
```

（`e.gao` 在放榜时已由 school.js:389 写入；高考分支有 `if (e.hs && !e.uni)` 守卫，中考分支不碰 `salaryK`，安全。）

## 4. D-2 · 补习没有长期代价（**这个取舍我定**）

### 4.1 我的取舍：**加代价，但只加在「非收益维度」**

| | 决定 |
|---|---|
| **收益端** | **完全不动**。`study +randInt(6,11)`、`INT +randInt(2,4)` 原样保留（A-08：1600 局正交设计 6/6 格为正，**方向可签字**；幅度不可签字，见 §0.1b） |
| **代价端** | 加重，且**让它不被年度结算抹平** |

**为什么是「加代价」而不是「保持轻量」**：
1. **Dynamics 4/10 是当前最弱的一环**（MDA 三层里最低）。一个「有收益、无代价」的系统 = 无取舍 = 零 Dynamics 贡献。A-08 刚确认补习是**确定为正**的收益（1600 局 6/6 格为正）——这恰恰使它成为当前**最明显的「无取舍」缺口**。
2. 但**代价不能落在收益端**，否则就是把 team-lead 刚验证过的正收益削掉，那是倒退。
3. 所以：代价落在 **健康（HP）**、**高考压力（分数）**、**叙事（倦怠事件）** 三条线上。

**为什么这样设计不会伤到休闲玩家**：只刷 1–3 次的玩家，代价为 0（下面的阈值都从第 4 次起）。代价只针对「无脑刷满」的极端玩法。

### 4.2 三条代价线

#### 代价线 ①：HP 累积（影响晚年寿命）

```js

```

|---|---|---|---|---|---|
| 累计 HP 代价 | −9 | −16 | −24 | −33 | −43 |

> HP 直接影响 `engine.js:1568-1576` 的晚年死亡风险 `(1 + max(0, 60 − HP) / 22)`。**代价是真实的，但要到晚年才兑现**——这正好补上「早年透支、晚年还账」的叙事闭环。

#### 代价线 ②：高考压力（内生于现有公式，最优雅）
