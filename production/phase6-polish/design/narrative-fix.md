### 2.2 三条迁移原则

1. **只改「不进存档」的 id。** 进存档的 flag / 资产 id，除非有强叙事理由，否则不动。
2. **每个 id 改名必须配一条幂等的 `migrateState()` 映射**（迁移两次结果一致）。
3. **进存档的 id 统一推迟到 B-04 批次一次迁完**，不要在本 Sprint 分批引入多次迁移风险。

### 2.3 `migrateState()` 建议片段

```js
/* engine.js migrateState() 内追加 —— 幂等，可重复执行 */
function migrateNarrativeIds(state) {
  // 1) 天赋 id: gangnam -> urban_hukou
  if (Array.isArray(state.perks)) {
    state.perks = state.perks.map(p => (p === 'gangnam' ? 'urban_hukou' : p));
  }
  if (state.flags && state.flags.gangnam) {
    state.flags.urban_hukou = true;
    delete state.flags.gangnam;
  }
  // 2) flag: kpop_boom -> culture_boom（随 e2012gangnam 删除）
  if (state.flags && state.flags.kpop_boom) {
    state.flags.culture_boom = true;
    delete state.flags.kpop_boom;
  }
  // 3) once 事件记录迁移：已看过被删事件的玩家，不再重复看保留版
  const seen = state.seen || state.done || null;
  if (seen) {
    if (seen.e2002)          seen.x_e04 = true;
    if (seen.e2012gangnam)   seen.x_e05 = true;
  }
  return state;
}
```

> ⚠️ 第 3 条的前提是确认 `once` 的记录容器名（可能是 `state.seen` / `state.done` / `state.onceIds`）。请 engineering-lead 用 `rg "once"` 定位后套用。

## 3. 两组重复事件的处置

### D-1：`e2002`（data.js:608） ↔ `x_e04`（data.js:1242）

| 维度 | `e2002` | `x_e04` |
|---|---|---|
| 形态 | 单 `eff`，**无 `choices`**（旧形态） | **带三选项 + `gamble`**（新形态） |
| `cond` | `{yearMin:2002, yearMax:2003}` | 同 |
| `era` / `once` | 均为 `true` | 同 |
| `eff` | `{WILL:3, CHA:2, STRESS:-8}` | 分散在三个选项里 |

#### 裁决：**删除 `e2002`，保留 `x_e04` 并改写文案（N-06）**

**三条理由**：
1. `x_` 前缀版是更先进形态——三选项给玩家能动性，符合本作「选择没有标准答案」的支柱。旧版单 `eff` 是被动演出。
2. 两条 `era:true` 且 `cond` 完全相同 → **2002 年可能连着抽到两条内容几乎一样的事件**（A-02 已指出高重复问题），叙事上是硬伤。
3. `e2002` 的 `eff` 无独特产出（无 flag 被外部引用），删除无功能损失。

**执行前检查（必做）**：
```bash
rg "e2002" assets/          # 确认无其他引用（need / ban / 结局 cond）
rg "x_e04" assets/          # 确认未被 ban
```
**迁移**：`seen.e2002 → seen.x_e04 = true`（见 §2.3）。

## 6. ⚠️ 货币口径问题（本 Sprint 顺带发现，需用户拍板）

**问题**：事件文案里**硬编码**的货币数字（「十亿」「几亿元」）不会被 `fmtMoney()` 转换。
内部量级 ÷180 = 人民币。因此：

| 文案 | 内部含义 | 玩家读到 | 冲突 |
|---|---|---|---|
| `x_s09`「账户里至少要有十亿」 | 1,000,000,000 内部 ≈ **556 万 RMB** | 玩家理解为「10 亿人民币」 | ❌ 差 180 倍 |
| `y2000`「几亿元」 | 几亿内部 ≈ **几百万 RMB** | 玩家理解为「几亿人民币」 | ❌ 差 180 倍 |
| `inv_imf_usd`「一美元从 900 元涨到近 2000」 | 韩元汇率残留 | — | ❌ 见 N-28 |

**建议（需拍板）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 事件文案**一律不写具体货币数字**，改用无数字或相对表述（「八位数」「三年也攒不到的钱」） | 低，改 3 处 |
| B | 文案走 `fmtMoney()` 动态渲染 | 中，需要事件 text 支持模板函数 |
| C | 不管 | 高，玩家会持续感到数值不自洽 |

> **我的建议：A**。本作是文字人生模拟，文案的文学性 > 数字的精确性。
