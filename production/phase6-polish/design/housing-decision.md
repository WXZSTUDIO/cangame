## 0. 明确推荐（先给结论）

> ## 🟢 推荐：**方案②为主干** + **方案①改写为「只抬 2025 年之后的斜率」作为配套**
>
> **如果只能选一个，选方案②。**
>
> 方案①原样（2025: 6.9→12）会让首套购房价格 ×1.74，**把「房价收入比 6–15×」这道回归门直接推到 18–46×，买房门必然 FAIL**。它并不是在修 B-04，而是在「把房子变得更贵」的同时「让买房更劣」。
>
> 配套修正不是抬绝对值，而是**抬 2025 年之后的年化斜率**：`2025: 7.4 / 2035: 10.0 / 2045: 13.5 / 2065: 24.0`，**2016 年及以前的分段完全不动**。这样房价收入比几乎不变，而持有期年化从 **1.70% → 3.55%**，与新增的现金 CPI（2.6%）对齐，让房子回到「抗通胀的保值资产」这一中国玩家的直觉位。

## 1. 先厘清一个被忽略的机制事实：房产的年化就是 `HOUSE_INDEX` 的年化

`market.js:237-242`：

```js
function housePrice(state, h) {
  const y     = fmtYear(state);
  const idx   = tableAt(HOUSE_INDEX, y);
  const jitter = 1 + (state.market.drift[h.id] || 0);
  return Math.round(h.base * idx * jitter);
}
```

关键两点：

1. **`HOUSES` 里每条的 `growth` 字段对房产完全不生效**（只有 `goodPrice()` 用了 `growth`）。房产增值**只**来自 `HOUSE_INDEX`。
2. `market.js:320` 的 drift 是**均值回归**过程 `d = drift*0.86 + hs*0.35 + gauss()*vol*0.35`，长期期望 ≈ 0。所以 `jitter` 只贡献波动，不贡献趋势。

**结论：房产年化 = `HOUSE_INDEX` 的年化。** 这也正好复现了 balance-analysis 实测的「房产年化约 5.0%」：

| 区间 | 现状指数 | 年化 | 方案①（原样） | 年化 |
|---|---|---|---|---|
| 1985 → 2025（40 年） | 1.0 → 6.9 | **4.95%** | 1.0 → 12 | **6.41%** |
| 2025 → 2065（40 年） | 6.9 → 10.0 | **0.93%** ⚠️ | 12 → 20 | **1.29%** ⚠️ |
| **2015 买 → 2065 卖**（典型持有期 50 年） | 4.3 → 10.0 | **1.70%** ⚠️ | ≈7.5 → 20 | **1.99%** ⚠️ |

> 扣掉 `upkeep` 0.8%–1.6%/年、贷款利息（2025 年 4.2%）、卖出 `propTax` 3.5% 之后，**房产在典型持有期的净年化是负的**。这才是 B-04「理性玩家永不买房」的真正根因——不是房价太低，是**持有期的指数不涨**。

## 2. 方案①：房价指数 2025: 6.9→12、2060: 9.85→20

### 2.1 它解决了什么

- 抬高了 **1985–2025** 段的年化（4.95% → 6.41%，+1.46pt），让「早买」的回报更显著。
- 让 `s05`（「江南的房价每天都在涨。中介说：再不买就永远买不起了」）这类叙事更有分量。

### 2.2 它没有解决什么（决定性）

1. **持有期年化仍然只有 ~2%**。玩家在 30–38 岁买入、持有到 80 岁，走的正是 2025→2065 这一段——**方案①完全没动这一段的问题**。
2. **房价收入比被推爆。** 以最典型的刚需标的 `h_apt_gangbuk`（市区老破小两居，`base 78,000,000`）为例：

| 口径 | 现状（2015，index 4.3） | 方案①（2015，index ≈ 7.48） |
|---|---|---|
| 房价（内部） | 335,400,000 | 583,000,000 |
| `careerIncome` 低值（32 岁） | 约 12,600,000 | 12,600,000（**不随年代缩放**） |
| `careerIncome` 高值（32 岁） | 约 31,600,000 | 31,600,000 |
| **房价收入比** | **10.6× – 26.6×** | **18.4× – 46.3×** ❌ |

> `careerIncome()`（career.js:483-491）**完全没有 `FIN_SCALE(year)`**——收入不随年代缩放。因此房价单边 ×1.74，等价于房价收入比单边 ×1.74。**买房门（6–15×）必然 FAIL，稳健流买房率 55–85% 必然崩塌。**

3. **与 A-01 晚年真空负向耦合**：买房门槛抬高 → 晚年「有房」成为少数富人专属 → 本次 Sprint 新增的 15–20 条晚年事件（遗物整理、金婚、老邻居、卖房换养老院）**受众面变窄**，空转率修复打折。

### 2.3 玩家体验推演（MDA / SDT）

| 维度 | 方案① 影响 |
|---|---|
| **Mechanics（机制）** | 纯调参，不新增任何决策维度。机制层仍是「买房 = 算 IRR」的单变量计算 |
| **Dynamics（动态）** 现状 4/10 | **收敛**：所有人都更晚买 / 更买不起。产生的不是策略分歧，而是共同挫败。Dynamics 无改善 |
| **Aesthetics（美学）** 现状 6/10 | 只产出一种美学：**挫败（买不起）**。本作主打的「人生模拟 · 一代人的命运切片」美学被削弱 |
| **SDT 自主感** 现状 7 | ↓ 玩家想买但被系统拒绝——这不是选择，是剥夺 |
| **SDT 胜任感** 现状 3（最弱） | ↓↓ 「我怎么努力都买不起」直接击穿最弱的一环 |
| **SDT 关联感** 现状 8 | 中性偏负（结婚率与 `own_house` 挂钩，love.js:494/559） |

> 一句话：**方案①是把一个数值问题（B-04）用另一个数值（价格）去压，结果是制造一个新的数值问题（房价收入比）。**

## 3. 方案②：不动房价，自住房给 `SEC+8 / MOOD+6 / 每年 STRESS−3`

### 3.1 设计意图

把「买房」从**单变量财务决策（IRR）**改造成**多变量人生决策**：

```
买不买房 = f( 财务：年化 ~1.7% − upkeep − 利息 − 摩擦   →  略亏
             , 安全感：SEC +8                            →  直接进结局评分与婚姻/育儿判定
             , 心情：MOOD +6                             →  长期低落会拖垮身体（data.js:360）
             , 压力流：每年 STRESS −3                    →  终身持续，对冲压力棘轮
             , 税负：自住房出售免 CGT（15%）              →  退出时补一档
           )
```

### 3.2 玩家体验推演（MDA / SDT）

| 维度 | 方案② 影响 |
|---|---|
| **Mechanics** | **新增一个非货币收益通道**。买房从「算IRR」变成「算 IRR + SEC + MOOD + 压力流 + 税负」。这是机制层的**加法**，不是调参 |
| **Dynamics** 4/10 → 预估 6–7/10 | **产生真分歧**：稳健流 / 家庭流买房（要 SEC、MOOD、终身减压）；激进流 / 机会流租房（要流动性去抓 `INVESTMENTS` 的时代机会）。**这是当前 Dynamics 4/10 最缺的东西** |
| **Aesthetics** 6/10 → 预估 7–8/10 | 给「家」一个情感定义。契合「发现 / 陪伴 / 表达」三种美学：玩家在房子里过完一生，晚年事件有叙事锚点 |
| **SDT 自主感** 7 → 8–9 | 两种活法都成立且不唯一正确 → 自主感的核心来源 |
| **SDT 胜任感** 3 → 5–6 | 提供一条**不靠暴富也能过好一生**的可规划路径：稳定、可预期、看得懂。这是当前最弱一环的唯一低成本补法 |
| **SDT 关联感** 8 → 8–9 | 可与婚姻（`love.js`）、育儿、晚年事件（孙辈回来看你、金婚、遗物整理）挂钩 |

### 3.3 与 S-02 五个参数的耦合（逐条）

| S-02 旋钮 | 与方案②的耦合 | 方向 |
|---|---|---|
| **① 单年资产性收益封顶 `3× incomeRef`** | SEC/MOOD/STRESS **不是资产性收益**，不进封顶核算 → 方案②提供了一个**不受封顶影响的价值通道** | 🟢 正向（互补，不打架） |
| **② 现金 CPI 2.6% + 应急金盾** | 现金有通胀成本，房产是**名义资产且不在 CPI 作用面** → 「把现金换成房子」成为对抗通胀的合理动作。**这给方案②补上了财务侧的一条腿**，让「财务略亏」变成「财务大致打平」 | 🟢🟢 强正向 |
| **③ 阻尼 0.75→0.62 + 漂移上限 8%** | 股票回报下降 → 房产的相对劣势自动缩小 | 🟢 正向 |
| **④ INVESTMENTS 年化预算 ≤22/30/37%** | 同上，机会端被削 → 房产的相对位置上升 | 🟢 正向 |
| **⑤ `stockFee 0.005` + CGT 15% + 自住房免征** | **关键交叉点**：`cgtExemptSelfLive: true` 让自住房退出时省 15%，等于给房产的横向对比补了 +15% 的一次性回报 | 🟢🟢 强正向 |

**方案② 与 S-02 五条全部同向，零冲突。** 而方案①与 ①（封顶基数不含房价）、⑤（`propTax` 若上调会加重买房摩擦）都需要额外协调。

### 3.4 对「晚年真空」（A-01）的连带价值 ⭐

这是方案②相对方案①的**最大增量**，也是本 Sprint 最被低估的一处协同：

1. **「活得到」层面**：S-01 现状是激进流平均寿命 36.9 岁、67% 熄灭，成年后无任何主动减压手段。方案②的 `每年 STRESS−3` 是**终身持续的被动减压**。若 35 岁购房并持有到 76 岁，累计 41 年 × 3 = **123 点 STRESS 减免**——约等于把 STRESS 上限（120）的整整一条命的压力消掉。**玩家更可能活到有内容的年岁**，否则死在 67 岁就永远看不到本次新增的 76+ 内容。
2. **「有话可说」层面**：房子是 15–20 条晚年事件最好的素材发生器——
   - `w_golden`（金婚：在这套房子里过了五十年）
   - `w_belong`（遗物整理：每一件东西都有房间号）
   - `w_neighbor`（老邻居凋零：楼道里的人一个个走掉）
   - `w_grand_visit`（孙辈回来看你：他认不出沙发的位置）
   - `w_sell_house`（卖房换养老院：要不要把家换成一张床位）
   - `w_downsize`（换小房：房子太大了，孩子不回来）
   方案①（房价 ×1.74）让这些事件的受众变成少数富人；方案②让**每个买房的人都能接上晚年的叙事**。
3. **「有代价」层面**：`gangnam_owner`（`base ≥ 260,000,000`）每年 `livingCost + 15,000,000`。方案②下就形成真正的档位取舍——**老破小（省钱、减压、低 CHA）vs 大平层（减压相同、每年多花 1500 万、CHA+7 / NET+8）**。这是方案①给不了的横向决策。
4. **与遗嘱系统（will-gdd）的接缝**：自住房是遗嘱分配里最有争议的标的（留给谁？卖了分钱？捐掉？）——方案②让房产在晚年叙事里有情感重量，遗嘱的「偏心 / 均分 / 慈善」选择才有痛感。

## 4. ⚠️ 落地方案②必须先解决的三个陷阱（否则会造出新的主导策略）

### 陷阱 1：`own_house` 当前对**任何**非 `jeonse` 房产都置位

```js
// market.js:434
if (kind === 'house' && !ref.jeonse) state.flags.own_house = true;
```

`HOUSES` 里非 `jeonse` 的包括：`h_villa_gj`（郊区小户型 base 45M）、`h_shop_gangnam`（**临街商铺**）、`h_villa_jeju`（**海边度假房**）、`h_bldg_seongsu`（**文创园整栋小楼**）。

→ 若直接给 `own_house` 挂增益，**买一套最便宜的郊区小户型（甚至商铺）就能白拿 SEC+8/MOOD+6/每年 STRESS−3**，立刻成为新的主导策略。

**必须引入 `selfLive` 标记**：

```js
// market.js HOUSES 新增字段
selfLiveable: true / false      // h_shop_gangnam / h_villa_jeju / h_bldg_seongsu / h_officetel_ydp = false
// buyProp：只有 rent === 0 且 selfLiveable 的房屋可设为自住
// state.market.selfLiveUid：全局唯一，切换需先解除旧的
```

### 陷阱 2：双重计分

现状 `engine.js:2241` 已有：

```js
score += state.flags.own_house ? 3 : 0;
```

若方案②再给 `SEC +8`，而 SEC 本身进结局评分 → **买房被计分两次**。叠加 `love.js:494/559` 的婚姻概率加成，买房会从「劣选择」直接翻成「**必选**」，形成新的主导策略。

**建议**：`score += own_house ? 3 : 0` **改为 +1 或直接移除**，由 `SEC +8` 统一承担。此改动属 S-03 范畴，**必须与 S-03 同批上线**（README 明确：S-02 与 S-03 不要同时按两套修复，先经济后评分）。

### 陷阱 3：`gangnam_owner` 的 1500 万/年 `livingCost` 会吃掉减压收益

`engine.js:1414-1422`：`if (state.flags.gangnam_owner) cost += 15000000;`

这笔钱在早期是巨款（≈8.3 万 RMB/年），会让「买大平层 = 纯亏」。
**建议**：把这 1500 万重新定义为「**物业费 + 税费 + 圈子开销**」并在 UI 明示，且**随 `CPI_INDEX` 而非固定值**上涨，避免晚期形同虚设、早期过于致命。

| # | 场景 | 处理 |
|---|---|---|
| E-1 | 玩家同时持有多套住宅 | `selfLiveUid` 唯一；增益只给一套。其余按投资房处理（收 CGT） |
| E-2 | 自住房卖出后买入新的 | 增益**不重复给** SEC/MOOD（一次性增益终身只给 1 次，记 `flags.self_live_bonus_taken`）；`STRESS−3` 随持有状态生效 |
| E-3 | 买商铺 / 度假房 | `selfLiveable:false` → 无增益，且**出售征 CGT 15%** |
| E-4 | 离婚 / 配偶去世 | `spouseBonus +2` 立即失效；`MOOD −6`（失去共同生活的家）——建议与晚年事件联动 |
| E-5 | 断供 / 房产被强制执行 | 清除 `selfLiveUid`，`SEC −8`、`MOOD −6`（增益对称回收），并触发一条危机事件 |
| E-6 | 租房（`jeonse: true`） | `ref.jeonse` 恒不给 `selfLive`；现状 `jeonse` 的 `cha: -2` 保留，作为「租房的隐性代价」 |
| E-7 | 老存档已有 `own_house` | 迁移时设 `selfLiveUid` 为其第一套非 jeonse 房产；**SEC/MOOD 不回溯补发**，只从下一年度起给 `STRESS−3` |
