## 1. 命名约定

```
au.<域>.<动作>[.<变体>]
```

- 全小写、点分隔、无大写无下划线
- **域**（domain）：`ui` / `year` / `card` / `result` / `exam` / `career` / `love` / `family` / `health` / `money` / `meta`
- 规则：`au.` 前缀保证全局唯一，便于 `grep 'au\.'` 一次性审计所有调用点

示例：`au.card.open`、`au.exam.reveal`、`au.milestone.up`

> 📌 与工程侧约定：**调用点只写 `AU.emit('au.xxx')`，音色实现集中在 `audio.js` 的一张表里**。换音色不需要动任何业务文件。

## 2. 【核心架构发现】用一个钩子覆盖全游戏，而不是改 119 个地方

这是本份文档最重要的结论，直接决定实现成本。

### 2.1 三个现成的天然钩子

| 钩子 | 位置 | 为什么它是最优注入点 |
|---|---|---|
| **`pushLog(state, text, type)`** | `engine.js:852` | 全游戏 **119 处**叙事结果都流经这里，且 **`type` 字段已经是情绪价层分类器** |
| **`renderItem(item)`** | `ui.js:1361` | 所有「弹出一张卡」（event / exam / invest / year）的唯一出口 |
| **`toast(msg)`** | `ui.js:126` | 通用 UI 反馈（失败、成就提示） |

### 2.2 `type` 字段 = 免费的情绪价层（Valence）

现状统计（实测）：

| `type` | 次数 | 现有色值（`style.css:209-214`） | 映射到 SFX |
|---|---|---|---|
| `'money'` | 33 | `--green-d` 绿 | → `au.result.good` ✅ |
| `'warn'` | 25 | `--red-d` 红 | → `au.result.bad` ✅ |
| `'muted'` | 40 | `#B4B1A0` 灰 | → 中性（**建议默认不发声**） |
| `'story'` | 11 | `--ink` | → 中性（默认不发声） |
| `'stat'` | 2 | `--blue-d` | → 中性 |
| `'year'` | 1 | `--gold-d` 分隔线 | → 由 `advance()` 接管 |
| `'end'` | 3 | **无 CSS 规则** ⚠️ | → `au.meta.ending` |
| `'system'` / `'fam'` | 各 1 | **无 CSS 规则** ⚠️ | → 兜底中性 |

> 🎁 **白送的价值层**：`green=好事 / red=坏事 / gray=中性` 的语义已经存在于代码与设计里。音频不需要自己发明一套分类，只要**跟随现有的 type**。这一条覆盖了全部 119 个叙事出口。

> ⚠️ **发现的小瑕疵（非音频职责，记录上报）**：`'end'` / `'system'` / `'fam'` 三种 type **没有对应的 `.line.*` CSS 规则**，会以默认色渲染。建议补齐或统一，否则结局行的视觉层级丢了。

### 2.3 【标记嗅探】零侵入拿到 ~100 个语义族

代码中大量 `pushLog` 文本以中文方括号族名开头：`【晋升】`、`【结婚】`、`【丧亲】`、`【放榜】`……

因此可以在 `pushLog` 内加**一行正则**：

```js
const m = /^【([^】]{1,6})】/.exec(text);   // 取出 "晋升"
```

配合一张 **「族名 → 音效」映射表**（§3.D/E/F/G），**无需修改 career.js / love.js / school.js / loan.js / market.js 任何一个文件**，就能让全游戏约 100 个人生事件各自发出正确的声音。

**这是本方案性价比最高的一个决策：1 行代码 + 1 张表 ≈ 100 个事件的声音。**

#### ⚠️ 但该方案有两个必须接受的代价（诚实披露）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **耦合到显示文案** | 若将来某人重写了 `【晋升】` 的文案或改掉方括号习惯，该事件的专属音会**静默降级**为通用 good/bad 音 | 降级是**优雅**的（不会报错、不会失声），可接受；但对 Top-8 里程碑（§3.D 标 ★）建议后续改为**显式 ID 埋点**，不依赖文案 |
| **文本正则的轻微开销** | 每个 log 一次正则 | ≤ 1μs，相对 `renderStream()` 每次全量 `innerHTML` 重绘可忽略 |

> ✅ **结论：接受。** 用「文案嗅探做广度覆盖 + 显式 ID 做关键保障」的混合策略。

### 2.4 【连线前必读】为什么不能把音效挂在 DOM 上

`renderStream()`（`ui.js:1343`）**每次调用都用 `innerHTML` 全量重建整个日志流**。任何挂在日志 DOM 节点上的事件监听器会在下一次 `renderStream()` 时被销毁。

➡️ **音频触发必须挂在逻辑层（`pushLog` / `renderItem` / `advance`），严禁挂在 `.line` DOM 节点上。**

> 💡 顺带一提：这个全量重建也是 PERF-01 的性能热点。音频侧不受影响，但**请工程侧勿在修性能时把音频钩子挪到 DOM 层**。

### B. 日志通用价层（来自 `pushLog` 的 `type`）

> 这一层是**兜底**：任何没有被 §3.D–G 精确捕获的事件都会落到这里。
> 设计约束：这是出现频率最高的一层，因此音色必须 **最朴素、最不抢戏**。

| ID | 触发点 | 触发条件 | 音效描述 | 优先级 | 必须 |
|---|---|---|---|---|---|
| `au.result.good` | `engine.js:852` `pushLog` | `type === 'money'` | 五声音阶**上行两音**（如 C5→E5），明亮但不跳跃 | **48** | ✅ |
| `au.result.bad` | `engine.js:852` `pushLog` | `type === 'warn'` | 下行两音（如 A4→E4），加低通变暗，**音量不加** | **50** | ✅ |

> 🔇 **关于 neutral 为什么建议默认不发声音**：一年往往同时产生 5–10 条 neutral 日志。为它们发声会立刻变成噪音墙，**这是同类文字游戏最常见的翻车点**。建议 MVP 期间 neutral 完全静默，把「有声音」变成一种**奖励性稀缺资源**。
> 若日后希望有声音，给一个 ≤60ms、音量 −24dB 的「笔尖沙沙」即可，并且仍受 §4 帧内合并保护。

## 4. 帧内合并（Frame Coalescing）—— 必须实现，否则必翻车

### 4.1 问题

玩家点一次「下一年」，`advance()` → `step()` 会**同步**执行这一长串：
`yearBase` → `marketTick` → `settleInvestments` → `careerTick` → `loveTick` → `familyTick` → `illnessTick` → `loanTick` → `checkAchievements` → `pickEvents`

**这期间通常会产生 3–10 条 pushLog。** 若每条都发声，一次点击 = 一堵墙般的杂音。这是文字模拟器最常见的音频失败模式。

### 4.2 解法：一帧只发一个声

在 `AU.emit()` 内把候选推入队列，用**微任务**（`Promise.resolve().then`）在当前同步任务末尾统一裁决，只播放**优先级最高**的那一个。

**理由**：`advance()` 内部是纯同步的（无 await），微任务会在它 + `renderItem()` 全部执行完之后才 flush → 天然涵盖「这一帧的所有的人生结算 + 卡片呈现」。**零依赖、零定时器。**

### 4.3 优先级裁决表（canonical）

| 优先级 | ID | 说明 |
|---|---|---|
| **100** | `au.meta.ending*` | 结局，绝对最高 |
| **90** | `au.meta.achievement` | 成就 |

| **80** | `au.exam.reveal` | 放榜 |

## 5. 连点降噪（Fast-forward Dampening）—— 空格快进专用

### 5.1 问题

`ui.js:1908` 的 keydown 监听：当 `actions` 里**只有一个按钮**时，空格/回车自动点击它。
玩家会**按住空格**快速刷年份 → **SFX 触发率可达 10+ 次/秒**。这是本作特有的、必须专门处理的风险。

### 5.2 解法：三档速率自适应

记录最近一次发声时间戳 `lastPlayAt` 与滚动窗口内的发声次数：

| 档位 | 触发条件 | 行为 |
|---|---|---|
| **正常档** | 间隔 ≥ 400ms | 正常播放，最小间隔 **80ms** |
| **快进档** | 间隔 200–400ms | 最小间隔抬到 **220ms**，且**丢弃优先级 < 70 的所有事件**（只留里程碑/结局/成就） |
| **连发档** | 间隔 < 200ms | 只播放 **优先级 ≥ 85** 的事件（结局、成就、丧亲） |

> 效果：慢玩时音效丰富；快刷时自动退让；**但真正重要的事（死了、成就、亲人走了）永远不会漏掉**。这正是设计意图——快进时不打扰，但不屏蔽关键时刻。

### 5.3 补充建议：连发档给一个「极轻的稳定 tick」

在连发档，与其完全静音，不如保留一个 **−30dB 的 20ms 木质 tick**（每 ~250ms 一次），让玩家确认「系统还在跑」。这个细节会显著提升连点时的手感。

> 范围边界：本轮**不动** cangame-mp。但因其复用同一份引擎逻辑，标注适用性以便将来迁移。

| 钩子 | 小程序适用性 | 说明 |
|---|---|---|
| `pushLog()` 价层嗅探 | ✅ **完全适用** | 引擎共用，`type` 字段与 `【】` 文案一致，是迁移性价比最高的一层 |
| `renderItem()` 卡片层 | ❌ 不适用 | 小程序渲染层不同，需在各自 UI 层重写挂载 |
| `advance()` 心跳 | ✅ 适用（逻辑层） | `step()` 是引擎函数，共用 |
| `checkAchievements()` 成就 | ✅ 适用 | 逻辑层共用，但 toast/徽章 UI 不同 → 音效挂载点需重写 |
| 帧内合并机制 | ✅ **强烈建议保留** | 纯 JS，与平台无关，`Promise` 微任务在小程序同样可用 |
