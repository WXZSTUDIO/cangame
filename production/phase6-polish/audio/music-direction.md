# CANGAME 音乐方向 · Music Direction

> 作者：阮和鸣（audio-director） · Phase 6 Polish · v1.0
> 项目：cangame「人生模拟」Web 版 v5.5.0
> 依据：已通读 `assets/*.js`（engine / school / career / love / loan / market / ui / data），所有结论均可回溯到代码行

---

## 0. 一句话结论（先给决策）

**推荐路径：SFX 先行，BGM 后置且有门控。**

cangame 是一款「读多听少」的文字人生模拟游戏。它的核心体验是**阅读与想象**，声音在这里的角色是「批注」而不是「配乐」。
基于代码实况（见 §2），我给出的建议是：

| 阶段 | 内容 | 判断 |
|---|---|---|
| **P6-A（本次 MVP）** | 纯程序化合成音效（10 个以内），**零音频文件、零依赖** | ✅ 强烈建议做 |
| **P6-B（门控）** | 单曲表达的极简 BGM，先只做「人生主界面」一条 | ⚠️ 需用户拍板是否值得投入 |
| **P6-C（远期）** | 阶段变奏、结局专属音乐 | ⏸ 暂缓 |

**理由一句话**：当前最大的完成度缺口是「点了没反应」的**即时反馈**，那是 SFX 的职责；而 BGM 在一个平均阅读时长占 80% 的游戏里，投入产出比显著低于 SFX，且是**听觉疲劳的唯一主要风险源**。

> 本文第 3–7 节给出完整的 BGM 方向（团队若拍板上线可立即执行），第 2 节给出为什么我仍建议把它排在 SFX 之后。

## 1. 听觉定位：这个游戏「应该是什么声音」

### 1.1 一句话听觉身份

> **一间有阳光的旧房间里，纸张翻动的声音。**

不是史诗、不是赛博、不是国风大编钟。是**纸质感、木质、有留白、有体温**的。

### 1.2 三条不可违背的定位原则

| 原则 | 含义 | 反例（禁止） |
|---|---|---|
| **克制 Restraint** | 任何单音 ≤ 400ms，任何一帧只发一个声 | 每个选项都「叮」一声的廉价手游感 |
| **不惊吓 No Startle** | 动态范围窄，靠**音区**而非**音量**承载情绪 | 坏事突然炸响——会被永久性静音 |
| **陪伴而非表演** | 音乐退到「空间」层，不当主角 | 情绪浓烈的弦乐高潮盖过阅读节奏 |

### 1.3 为什么「鏗鏘 Dense Orchestral」是错的

- 游戏单局 105 个年份 step，一局 5–15 分钟。**任何有强节拍/强旋律的音乐，在 8 分钟后都会从「好听」变成「烦躁」。**
- 它在跟**你的阅读内部 voice** 抢同一个注意力通道（语言/叙事层）。
- 玩家典型场景：**睡前、通勤、工位摸鱼**。这是三个「不能被打扰」的场景。

## 2. 关键：为什么我建议 BGM 后置（代码实况依据）

这不是偷懒，是基于以下从代码里读出来的事实：

### 2.1 「推进」是唯一核心动词，且节奏完全由玩家掌控

`ui.js:1434 advance()` → `step()` 是整个游戏的节拍器。玩家点一下走一年，也可以按**空格/回车**连发（`ui.js:1908` 的 keydown 监听会在只有一个按钮时自动点击）。

**推论**：玩家可以以 **≥10 次/秒** 的速度推进。音乐无法也不应该跟上这个节奏——它必须是**独立于 step 的连续时间层**。这意味着 BGM 需要自己的状态机（见 `showScreen()` / `body.dataset.screen`），这是一份额外的实现成本。

### 2.2 屏幕是有明确状态机的（这是好消息）

`ui.js:133 showScreen()` 已经写入 `document.body.dataset.screen`，取值：`screen-title` / `screen-create` / `screen-game` / `screen-market` / `screen-end`。

**这是现成的音乐状态切换钩子，不需要新增任何数据结构。** 见 §5。

### 2.3 但游戏内有大量「非音乐友好」的空转时间

玩家在 `screen-market`（买房/买车/股票，`ui.js:1609 openMarket()`）和人际关系页（`renderRelView()`）会停留做**决策计算**。这段时间音乐无所适从——继续放会腻，切换会乱。

### 2.4 结论

**先用 SFX 把「反馈」这个真空补上**（这是玩家能立刻感知到的完成度提升），**把 BGM 作为一个带真实成本的后置决策**。若要做，请按下节的方向做——不要做「一首循环 2 分钟的中国风 mp3」，那是所有选项里最糟的。

## 3. 若上线 BGM：音乐基调

### 3.1 调式决策：五声音阶（宫商角徵羽）——这是本项目最重要的音乐决策

**采用中国五声音阶（不含 fa / si），不用西洋大小调。**

技术理由（不只是「听起来中国」）：

1. **五声音阶天然无半音冲突**，任意音叠加都协和 → **长时间循环极难产生疲劳**。这是 BGM 疲劳问题的根本解法，不是靠换曲子缓解，而是从音高材料层面消灭不协和。
2. 玩家演奏/哼唱门槛低 → 旋律可被记住（fragile but memorable）。
3. 与本作「轻中国⻛」视觉调性对齐（`--gold-d` / `--ink` / `--paper` 色系）。

> ⚠️ 注意：**不要用「五声音阶 + 大编钟 + 古筝刮奏」的俗套组合**。那是旅游宣传片。我们的组合见下。

### 3.2 乐器与织体（Sonora Palette）

| 层 | 乐器 | 角色 | 密度上限 |
|---|---|---|---|
| **旋律层** | 钢琴（立式钢琴音色，不要三角钢琴的华丽） | 唯一主角，单音陈述 | 每 4 秒 ≤ 3 个音 |
| **点缀层** | 古筝 或 琵琶（拨弦，留白） | 句读、呼吸，不是旋律 | 每 8 秒出现 1 次 |
| **衬底层** | 弦乐 pad / 低音提琴长音 | 情绪底座 | 持续但极低，`-30dB` 以下 |
| **环境层** | 纸、木质家具、极远处市井白噪 | 空间感 | `-38dB`，近乎不可闻 |
| **节奏层** | **无** | — | **禁止打击乐** |

**为什么没有鼓**：打击乐是听觉疲劳的第一来源，且会把玩家的阅读节奏拽到音乐节奏上。**这个游戏里禁止一切有节拍的打击乐。**

### 3.3 情绪曲线（随人生阶段演进）

对齐人生阶段，注意：**目标是「同一主题的不同光照」，不是八首不同的曲子。**

| 人生阶段 | 代码锚点 | 情绪 | 音色处理 |
|---|---|---|---|
| **0–6 童真** | `state.age <= 12`（`engine.js:1049` 走单选项叙事） | 轻、好奇、无负担 | 高八度、钢琴单音 + 木琴点缀、留白最多 |
| **7–18 求学** | `schoolStageOf()` / `makeExamEvent` | 略紧、期待 | 加入古筝点缀，节奏仍自由；考试段落可加极轻心跳感低频 |
| **19–30 挣扎** | `careerTick` / `loveTick` / `loanTick` | 温热、不确定 | 中音区，pad 增厚一点；这是全曲情绪最「实」的一段 |
| **31–50 承重** | `familyTick` 父母衰老、`illnessTick` | 沉、稳、闷 | 降到低八度，钢琴加弱音踏板感（更多低通） |
| **51–70 回望** | 退休 `engine.js:1518`、子女离家 | 淡、远、释然 | 稀疏化，点与点之间拉长到 6–8 秒 |
| **71+ 暮年** | 接近 `END_AGE = 105` | 极简、近乎无声 | 只剩 pad + 偶尔单音；**这是故意的「音乐退场」** |

### 3.4 年代感：不要试图做「年代还原」

**代码事实**：出生年 `randInt(1955, 2005)`（`engine.js:506`），`endAge = 105`（`data.js:11`）。
→ **游戏内年份跨度约为 1955 – 2110**（含大量近未来年份）。

**推论（重要）**：

- 不存在任何一种「年代音乐」能覆盖 155 年跨度（其中一半在未来）。
- 现存年代事件只覆盖 **1997 / 1998 / 2002 / 2008 / 2012 / 2020 + AI 时代**（`data.js:603–1258` 的 `era: true` 条目），**纯音乐无法承载年代标识**。

**正确做法**：
- **年代感交给 SFX 承载**（老收音机噪声、拨盘电话、BP 机、敲击键盘声），不交给 BGM。
- **BGM 保持「超时间 Outside of Time」**——一首不属于任何年代的曲子，反而能覆盖全部年代。这是低成本且不会出错的方案。
- 唯一例外：**若将来要强化年代**，可在 `pickEvents()` 的 `era` 分支（`engine.js:1052`）触发时叠一层极短的年代 SFX 印花（sting），而非换 BGM。

> 📌 附带一条越界提醒（建议转给 narrative owner）：`data.js:608 / 1242` 年代的 era 事件里出现了**韩国地名/语境**（光化门、整座城变成红色的海、江南 Style、`e2012gangnam`）。若本作设定是中国人生模拟，这是叙事一致性缺口，**不属于音频职责**，仅作记录上报。

## 4. 变奏策略：一首主题 ≠ 一首 Loop

### 4.1 成本现实

独立开发者不可能产出 8 首高质量 BGM。**正确做法是「1 主题 + 4 变奏 + 智能留白」，而不是 8 首曲子。**

### 4.2 三段式织体模型（推荐）

```
Core Loop  (≈60–90 秒，8–16 小节，五声音阶，无鼓)
   ├── Variant A：童年版 —— 高八度、木琴替代部分钢琴、古筝点缀减半
   ├── Variant B：青壮年版 —— 标准织体、pad 最厚
   └── Variant C：暮年版 —— 低八度、大量留白、几乎只剩 pad
```

切换由 `state.age` 驱动（阈值见 §3.3），**在 `yearBase()` 之后检查即可**，不需要新系统。

### 4.3 反疲劳三招（这是本节的核心价值）

| 招式 | 做法 | 为什么有效 |
|---|---|---|
| **① 呼吸间隙 Gap Strategy** | 每轮 Core Loop 结束后，随机插入 **4–16 秒**的近乎静音窗口（只剩 pad 极弱底噪） | **最被低估的抗疲劳手段。**「一直在响」才是循环感的来源；有停顿才会感觉是活的。玩家几乎不会注意到音乐停过 |
| **② 相位错位 Phase Offset** | 进入某一阶段时，不从 loop 头开始播，而从**随机偏移点**淡入 | 消除「又从这里开始了」的识别点 |
| **③ 随机 micro-detune** | 每次 loop 播放时的 playbackRate 微扰 ±0.3%，钢琴音符起音时间抖动 ±15ms | 消除机械重复感（Web Audio 原生支持，零成本） |

> ❌ **明确反对**：常见做法是「准备 3 首曲子轮换」。那只会把疲劳周期从 8 分钟延长到 24 分钟，同时在切换处制造突兀。宁可一首曲子 + 留白。

## 5. BGM 状态机（若上线，挂在现成钩子上）

不需要新数据结构，直接复用 `showScreen()` 的 `body.dataset.screen`：

| dataset.screen | 音乐状态 | 说明 |
|---|---|---|
| `screen-title` | Title Sting + 稀疏 pad | 标题页，可有一句主题陈述（唯一允许「完整旋律出现」的地方） |
| `screen-create` | 延续 title，音量降到 60% | 捏人阶段需要专注思考 |
| `screen-game` | Core Loop（按 §3.3 选 variant） | 主游戏，最低音量（`-24dB` 相对 SFX） |
| `screen-market` | **音量降到 40%，或淡出到只剩 pad** | 决策计算场景，音乐应退让 |
| `screen-end` | Ending Sting → 长余韵 → 静 | 结局页，音乐收束（唯一允许「终结感」的地方） |

**切换统一要求：所有淡入淡出 ≥ 1.2 秒**（`linearRampToValueAtTime` / `exponentialRampToValueAtTime`）。禁止硬切。

## 6. 验收标准（便于 QA 判定）

| # | 标准 | 判定方式 |
|---|---|---|
| M1 | 单音时长 ≤ 400ms（ending sting 除外 ≤ 3s） | 波形检查 |
| M2 | 峰值电平不高于 SFX 峰值 −12dB | LUFS / 峰值测量 |
| M3 | 连续播放 15 分钟无明显烦躁感 | 5 人盲听，≥4 人可接受 |
| M4 | 无任何打击乐（鼓、掌、木鱼节拍） | 频谱/听感检查 |
| M5 | 全部音高落在五声音阶内 | 乐谱核对 |
| M6 | 屏幕切换淡入淡出 ≥ 1.2s，无爆音 | 切换扫频测试 |
| M7 | 手机扬声器（单声道）下旋律仍清晰可辨 | 见 `mixing-notes.md` §4 |
