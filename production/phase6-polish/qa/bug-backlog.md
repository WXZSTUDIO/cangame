## S-01 · 高风险决策是"自杀按钮"，激进/亡命两条玩法路径不可玩

**严重度** S · **模块** `assets/engine.js`（`yearBase` / `resolveEvent`）· **分类** 数值 / 生存

**现象**
| 画像 | 平均寿命 | 熄灭 | 病逝 | 30岁压力(中位) |
|---|---|---|---|---|
| 稳健流（低风险+治疗） | 82.9 | 3 / 200 | 37 / 200 | 2 |
| **激进流**（期望效用最大+治疗） | **36.9** | **134 / 200（67%）** | 66 / 200 | **111** |
| **亡命流**（盲选高风险+不治疗） | **30.6** | **137 / 200（68.5%）** | 63 / 200 | — |

HP 中位轨迹（`probe-hp.js`，每组 80 局）：

| 风格 | 20岁 | 25岁 | 30岁 | 35岁 | 40岁 |
|---|---|---|---|---|---|
| low+treat | 117 | 120 | 120 | 120 | 120 |
| ev+treat | 113 | 120 | 120 | 117 | 117 |
| **high+notreat** | 110 | 108 | **69** | **45** | **35** |

压力轨迹：high+notreat 组 20 岁 34 → 25 岁 85 → 30 岁 **111**（上限 120）→ 40 岁 114，之后**再也降不下来**。

**根因**
1. 压力恢复是**固定值** `s.STRESS -= 7`/年，而高风险事件每年累积 +3~+8，且压力越高触发的负面事件越多 → 单向棘轮。
2. 高风险选项的增益/减益系数 `scaleEff(base, 1.7, 1.35)` 对称放大，但**增益是一次性的、减益（压力）是累积的** → 长期必亏。
3. 成年后没有任何主动减压手段（学生时期有"和同学玩"，成年后消失）。

**影响**
一半以上的玩法路径（炒股/创业/借贷/举报/站队）在统计意义上是**必死**的。玩家第一次尝试激进玩法会在 37 岁前猝死，且**得不到任何反馈说明为什么死**。

**复现**
```bash
"$NODE" playtest-run.js    # 见 out/summary.md §1：激进流平均寿命 36.9，熄灭 ×134
"$NODE" probe-hp.js        # 见 out/probe.md §1：high+notreat 30岁压力 111
```

**建议修复（参数级）**
```js
// 1) 压力恢复改为「固定 + 比例」，让高压状态有回归通道
s.STRESS -= 7 + s.STRESS * 0.12;

// 2) 高风险选项：提增益、降减益，让长期期望转正
scaleEff(base, /*增益 1.7 →*/ 2.4, /*减益 1.35 →*/ 1.15);

// 3) 成年期补一套主动减压行动（每年可选 1 次）
//    休假旅行 / 健身 / 心理咨询 → STRESS -12, HP +4, MONEY -X
```

**验收标准**：激进流平均寿命 ≥ 60 岁；熄灭率 ≤ 25%；激进流 S 级占比与稳健流差距 ≤ 20pp。

**回归测试**：需在 `tests/regression-suite.md` 补一条「高风险长期生存」用例 —— 固定种子跑 200 局激进流，断言平均寿命 ≥ 60。

## S-03 · 评分无区分度，89%–94% 的局都是 S 级

**严重度** S · **模块** `assets/engine.js:2225` `scoreOf()` · **分类** 数值 / 反馈

**现象**
| 画像 | 平均分 | 标准差 | S 级占比 |
|---|---|---|---|
| 稳健流 | 93.8 | 18.8 | **89%** |
| 探索流 | 97.0 | 13.6 | **94%** |
| 摆烂流 | 85.3 | 21.4 | 59% |
| 激进流 | 83.0 | 15.3 | 24% |
| 随机基线 | 82.9 | 20.5 | 45% |

「摆烂流」（不升学不理财不买房不婚育）仍拿到 **59% 的 S 级**。

**根因**：`scoreOf()` 每一项都封顶，而封顶点远低于实测属性水平。

```js
score += Math.min(38, Math.sqrt(Math.max(0, worth) / 1e8) * 3.2);   // 净资产项
```

| 净资产（人民币） | 内部单位 | 该项得分 |
|---|---|---|
| 55.6 万 | 1e8 | 3.2 |
| 5556 万 | 1e10 | 32.0 |
| **7834 万** | **1.41e10** | **38（封顶）** |

**净资产项在 7834 万元就吃满，而稳健流中位 26.14 亿 = 饱和点的 33 倍。**
同理 FAME 项（`min(25, FAME×0.35)`，FAME 均值 108 → 封顶）、NET 项（`min(15, NET×0.12)`，NET 均值 163 → 封顶）全部饱和。

**复现**
```bash
"$NODE" playtest-run.js && "$NODE" analyze2.js   # out/strata.md §7 评分区分度
```

**建议修复**
```js
score += Math.min(38, Math.sqrt(Math.max(0, worth) / 1e8) * 0.9);  // 饱和点 → 98.8 亿
score += Math.min(25, s.FAME * 0.16);                              // 饱和点 → FAME 156
score += Math.min(15, s.NET * 0.07);                               // 饱和点 → NET 214
```
（若 S-02 先修，净资产项可保持 `×3.2` 不动 —— 两条建议**不要同时上**，先修经济再看评分。）

**验收标准**：稳健流 S 级 ≤ **35%**；各画像标准差 **≥ 12**；摆烂流 S 级 ≤ 20%。

## A-02 · 47% 的事件是"模板三选一"伪选择，第三个选项恒为劣势项

**严重度** A · **模块** `assets/engine.js`（`eventChoices()` / `scaleEff()`）· **分类** 设计

**现象**（`audit-choices.js`）

| 自带选项数 | 事件数 | 占比 |
|---|---|---|
| **0（走模板）** | **114 / 241** | **47%** |
| 2 | 1 | 0% |
| 3（手写） | 126 | 52% |

模板公式：
```
选项1（低风险）: eff = base × 0.6(增益) / ×0.45(减益),  STRESS -2
选项2（中风险）: eff = base × 1.0  / ×1.0
选项3（高风险）: eff = base × 1.7  / ×1.35,            STRESS +4, 45% 概率赌注
```

赌注期望：MONEY 类 `0.45×(+1.5|M|) + 0.55×(−0.7|M|) = +0.29|M|`（**正 EV**）。

**结论**：
- `base` 为正（好事）→ 选项3 期望 ≥ 选项2 ≥ 选项1 → **理性玩家永远选 3**
- `base` 为负（坏事）→ 选项1 期望 ≥ 选项2 ≥ 选项3 → **理性玩家永远选 1**
- **第三个选项恒为劣势项，从来不该被点**

**叠加问题**：`CHOICE_TEMPLATES` 每个 tag 只有 **4 组**文案（study/work/love/money/health/family/social/risk/moral/default 各 4），高重复感。

**复现**
```bash
"$NODE" audit-choices.js   # out/choices.md §4 模板公式、§8 文案池
```

**建议修复**
```js
// 1) 把「倍率三选一」改成「真正的权衡」：选项1 牺牲上限换确定性，选项3 赌上限但吃痛
//    例：选项1 = base × 1.0 + 一个机会成本（如 STRESS -6 但 GROW -3）
//        选项2 = base × 1.4
//        选项3 = base × 2.2（成功）/ ×（-1.6）（失败）  → EV ≈ 选项2，但方差不同
// 2) CHOICE_TEMPLATES 每 tag 从 4 组扩到 10+ 组
// 3) 优先给 Top10 高频事件（confess / inb_* / famask / ill / grad / major）写手写选项
```
**注意**：手写选项质量很高——241 条事件里 eff 完全重复的手写选项只有 **1 条**（`f2_pet1`），eff 为空的 0 条。**问题只在模板生成的 114 条，不在手写部分。**

**验收标准**：模板事件占比 ≤ 25%；每 tag 文案 ≥ 10 组；对随机 20 条模板事件做 EV 检查，不应存在"某一选项在所有情形下均被支配"。

## A-11 · 六个金额入口没有 NaN 净化 —— UI 输入框留空就能废掉整局

**严重度** A · **模块** `assets/loan.js` / `assets/market.js` · **分类** 健壮性 / 数值
（REG-01 追加验证 B，engineering-lead 的 R-05 转派；他已在 UI 出口加 `num()`，本条是**上游**）

**现象**：`scripts/probe-nan.js` 定向复现，**16 组「脏入参 → 数值污染」**：

| 入口 | 位置 | 会被污染的入参 |
|---|---|---|
| `borrow(state, id, amount)` | loan.js:82 | NaN / undefined / `'abc'` |
| `repayLoan(state, idx, amount)` | loan.js:109 | NaN / undefined / `'abc'` |
| `buyStock(state, id, shares)` | market.js:464 | NaN / undefined / `'abc'` |
| `sellStock(state, id, shares)` | market.js:481 | NaN / undefined / `'abc'` |
| `repayDebt(state, amount)` | market.js:498 | NaN / undefined / `'abc'` |
| `buyProp(…, qty)` | market.js:414 | `'abc'`（**`qty \|\| 1` 挡不住非空字符串**） |

（`null` / `''` / `Infinity` 是安全的：`Math.round(null)`=0 被 `<=0` 拦下，Infinity 被 `> max` 拦下。）

**根因（系统性，不是笔误）**：
```
NaN <= 0      → false     // if (x <= 0) return 这类守卫拦不住 NaN
NaN > max     → false     // 上限守卫同样拦不住
clamp(NaN,0,100) → NaN    // 引擎的 clamp 不是 NaN 守卫（Math.max(a, Math.min(b, v))）
```
`buyStock` 里 `const n = Math.floor(shares); if (n <= 0) return;` —— NaN 直接穿过，
然后 `state.stats.MONEY -= NaN` → **MONEY 永久变 NaN，不可逆**。

**传播链（实测）**：
```
buyStock(id, NaN) → MONEY = NaN → netWorth() = NaN → scoreOf() = NaN
                                       ↓
                        fmtMoney(NaN) = "0元"  ← (NaN||0) 把 NaN 吞成 0
```
于是玩家看到的是「现金 0 元、净资产 0 元，但结局页评分 **NaN**」——这正是 R-05 里两种症状并存、却对不上的原因。

**重要结论**：**300 局正常玩法（含随机市场买卖）零 NaN、零崩溃。**
R-05 不是"数值系统算崩了"，而是**输入层没做净化**。属 **B 类（脏存档 / 畸形输入可达）**，不是 A 类。

**复现**
```bash
"$NODE" probe-nan.js   # out/nan-probe.md §1 静态审计 / §2 传播链 / §4 运行时追踪
```

**建议修复**
```js
// (1) engine.js 顶部加一行工具（clamp 旁边）
function safeNum(v, fb) { const n = Number(v); return Number.isFinite(n) ? n : (fb === undefined ? 0 : fb); }

// (2) 六个入口第一行净化（各 1 行）
const amt = safeNum(amount, 0);            // borrow / repayLoan / repayDebt
const n   = Math.floor(safeNum(shares, 0)); // buyStock / sellStock
const q   = Math.max(1, Math.floor(safeNum(qty, 1)));  // buyProp

// (3) loan.js annualPayment 补年份守卫（脏存档里 years=0 → Infinity）
const per = l.principal / Math.max(1, l.years);

// (4) marketMigrate 顺手消毒持股记录
m.stocks = (m.stocks || []).map(p => ({ id: p.id, shares: safeNum(p.shares,0), cost: safeNum(p.cost,0) }))
                           .filter(p => p.id && p.shares > 0);
```

**验收标准**：`probe-nan.js` §1 的污染命中数从 **16 → 0**；§4 运行时追踪保持 0。

## B-10 · 跨局状态残留：`choiceTexts()` 把缓存直接写在共享的 `EVENTS` 数据表上

**严重度** B · **模块** `assets/engine.js:1005-1012`（`choiceTexts`）· **分类** 状态污染 / 可复现性

**现象**：事件选项的文案模板被缓存进 **事件定义对象本身**，而 `EVENTS` 是模块级 `const` 数据表，
页面刷新前一直存活：

```js
function choiceTexts(state, ev) {
  if (!ev._ct) {                                   // ← 缓存挂在共享数据上，不挂在 state 上
    const tag = inferEventTag(state, ev);
    const pool = CHOICE_TEMPLATES[tag] || CHOICE_TEMPLATES.default;
    ev._ct = { tag: tag, i: randInt(...), txt: pool[randInt(...)] };
  }
  return ev._ct.txt;
}
```

三条后果：

1. **同页面第 2 局起，事件选项文案不再重新抽样** —— 一直沿用第 1 局抽到的那套。
2. **童年（≤18 岁）首次触发时定下的 `tag` 会带到成年** —— `inferEventTag()` 里有 `if (state.age <= 18) w.study += 3`，
   所以同一条事件如果第一次在童年命中，成年后再命中时仍会显示"学业味"的选项文案。
3. **随机数消耗量依赖历史** —— 第 1 局消耗了 `randInt`，第 2 局直接命中缓存不消耗。
   后果是**同一份代码跑两次，结果不同**：这是我自己的 REG-13 变成 flaky 测试的直接原因
   （未清缓存时，同种子两次构造的存档摘要分别是 `f9dee792` / `96e67e28`，长度相同但内容不同）。

**实测**：跑完一局后，vm 上下文里 25 张主要数据表中**只有 `EVENTS` 被改写**（65863 → 66648 字节，增量全是 `_ct`）。

**复现**
```bash
"$NODE" regression-run.js REG-13    # 最后一行「用例可复现」即本条的自检
```
> 修复前该行 FAIL；我在用例里加了 `resetChoiceCache()` 才让它变绿 ——
> **注意那是测试侧的规避，不是游戏侧的修复**。游戏侧仍需按下面改。

**建议修复**（2 行，把缓存从数据表挪到局内状态）
```js
function choiceTexts(state, ev) {
  if (!state._ct) state._ct = {};                    // ← 挂在当前这局上，不挂在 EVENTS 上
  if (!state._ct[ev.id]) {
    const tag = inferEventTag(state, ev);
    const pool = CHOICE_TEMPLATES[tag] || CHOICE_TEMPLATES.default;
    state._ct[ev.id] = { tag: tag, i: randInt(0, pool.length - 1), txt: pool[randInt(0, pool.length - 1)] };
  }
  return state._ct[ev.id].txt;
}
```
> 副作用：`state._ct` 会进存档（每条事件 3 个字段，量级几十条，可忽略）；老存档没有这个字段，`|| {}` 已兜住。
> 若不想进存档，改用模块级 `const __ct = new Map()`，key 用 `state.seed + '|' + ev.id` 亦可。

**验收标准**
1. 同一 vm 上下文连跑两局（同种子），`JSON.stringify(state)` 除 `seed`/`createdAt`/`updatedAt` 外完全一致；
2. `EVENTS` 跑完一局后 `JSON.stringify` 的长度**不变**；
3. 一条事件在童年首次命中后，成年再命中时的 `tag` 与直接在成年命中时一致（不再被童年污染）。

## C-08 · REG-07「骑手 vs AI 终局净资产倍数」是 flaky 门 —— 门限与噪声同量级，不可签字

**归属**：测试域自伤。由 10-08 红门绿端可达性体检发现（`scripts/gate-distance.js`）。

**性质**：不是"门错了"，是"**这道门的读数不能作为签字依据**"。
它现在是红的，但即使 A-03 修好了，它红不红取决于当天运气。

### 实证：同一份代码、同一 N=120，五次复跑

| 次 | 倍数 | 骑手终局净资产中位 | AI 终局净资产中位 |
|---|---|---|---|
| 1 | **1435.24×** | 401.3万 | 57.60亿 |
| 2 | 317.61× | 1716.3万 | 54.51亿 |
| 3 | 419.36× | 1284.6万 | 53.87亿 |
| 4 | 302.15× | 2422.8万 | 73.21亿 |
| 5 | **1019.58×** | 504.7万 | 51.46亿 |

**摆动 302× ~ 1435×（4.7 倍）**，门限是 150×。分子（AI）稳定在 51~73 亿，
**摆动几乎全部来自分母**（骑手净资产中位 401 万 ~ 2423 万，4.8 倍）。

### 根因

**比值 + 重尾分母**。与 §2.9 里给主理人的那条方法论更正同源：
> 比值降噪只对「水平量」成立。当分子分母**都是重尾量**时，比值**放大**噪声。

骑手组的终局净资产被彩票 / 股票 / 债务的重尾主导，40 局的样本量压不住。

### 建议（三选一，我倾向 1）

1. 改为**对数差**：`log(AI 中位) − log(骑手 中位) ≤ log(150) ≈ 5.01`（对数后重尾被压平）；
2. REG-07 用**固定种子**（`withSeededRandom`）跑，牺牲样本独立性换可复现；
3. 分母换成**职业收入中位**（低噪声）而不是终局净资产。

**签字前的处理**：在改口径之前，**REG-07 的 `gap` 一条不得作为签字依据**，
只能作为观察项；A-03 的验收以「换职业率 ≥ 0.25」那一条为准。
