## 3. 抽取逻辑实测

源码位置 `assets/engine.js:1051-1057`（`pickEvents`）：

```js
// 年代事件：窗口开启的年份必触发一个（每个出生年份都有自己独有的时代切片）
const era = weighted.filter(x => x.ev.era);
if (era.length) {
  const e = era[randInt(0, era.length - 1)].ev;   // ← 随机取 1 条
  picked.push(e);
  weighted.splice(weighted.findIndex(x => x.ev === e), 1);
}
```

**机制拆解（关键）**：

1. era 事件有一个「保证位」——窗口开启的年份**必触发 1 条**（随机取）。
2. 但被选中之后，代码只把**这一条**从候选池 `weighted` 里 splice 掉；
   **同一窗口里的其它 era 事件仍然留在 `weighted` 里**。
3. 而 `count = state.age <= 12 ? 1 : (chance(0.35) ? 2 : 1)`，
   13 岁以上每年有 35% 概率抽第 2 条事件 —— **第 2 条有可能正好是另一条 era 事件**。

> 所以准确答案是：**既不是「遍历全部匹配」，也不是「严格只触发一条」**；
> 主路径是「保证 1 条」，但存在一条漏网路径导致同年双触发。实测见下。

### 3.1 `pickEvents()` 单次返回的 era 事件条数分布（3131 次采样）

| 单次返回 era 条数 | 次数 | 占比 |
|---|---:|---:|
| 0 | 2440 | 77.93% |
| 1 | 690 | 22.04% |
| 2 | 1 | 0.03% |

- 最大条数：**2**；出现 ≥2 条的次数：**1 / 3131（0.03%）**
- 判定：⚠ **同年双触发确实存在**，概率约 0.03% —— 需要 `count=2`（13 岁以上 35%）且第 2 抽正好命中同窗口的另一条 era

**修复建议（1 处，2 行）**：选完 era 之后把候选池里剩余的 era 全部移出，只保留保证位那一条。

```js
const era = weighted.filter(x => x.ev.era);
if (era.length) {
  const e = era[randInt(0, era.length - 1)].ev;
  picked.push(e);
  // ↓ 原来只 splice 掉被选中那条；改为把所有 era 移出候选池
  for (let i = weighted.length - 1; i >= 0; i--) if (weighted[i].ev.era) weighted.splice(i, 1);
}
```

## 5. 附带发现：童年期 era 事件独占当年唯一名额

`pickEvents` 里 `count = state.age <= 12 ? 1 : (chance(0.35) ? 2 : 1)`，
而 era 事件是**先于**普通事件被 push 进 `picked` 的，且计入 `count`。
因此 **0-12 岁只要命中一条 era 事件，该年就不会再有其他事件**。

- 0-12 岁有事件的年份采样数：2474
- 其中含 era 事件的年份：236
- 其中**只有** era 事件（无其他事件）的年份：184（占含 era 年份的 78%）
