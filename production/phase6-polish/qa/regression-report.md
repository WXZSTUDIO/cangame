**F-06 ⚠️ REG-11 守卫门贴门限**

#### ⑤ 本轮新发现（F-08 ~ F-12，均为门/测试代码缺陷，**已定位未改**，等裁定）

**F-08 🟡 REG-10 名义门被实得门完全支配 → 冗余**
实得门 `kMed ≥ 1.5 × 2.80 = 4.20` **严格蕴含**名义门 `kMed ≥ 3.50`。
名义门永远不可能成为 binding 约束 —— 它能红，但红的时候实得门一定也红，它不提供任何额外判定力。
→ 建议：降级为观察项（保留显示，不参与判定），或删除。

**F-09 🔴 `catch (e) { continue; }` 静默丢局 → REG-11 / REG-12 的崩溃信号完全丢失 + 幸存者偏差**
`regression-run.js:445`（REG-11 单元格循环）与 `:595`（REG-12）：跑崩的那一局不计数、不告警，
只是从样本里消失。后果有二：① 崩溃率再高也进不了 crash 计数；② 统计量算在**幸存者子样本**上。
`crash-step` 注入实证：60 局里 56 局被静默丢弃，剩 4 局照样算出「熄灭占比 0.25」并**恰好压线判绿**。
→ 建议：改成 `crash++; continue;` 并在用例末尾断言「有效样本 ≥ 90% × N」。

**F-10 🔴 `catch (e) { }` 静默吞异常 → 「零崩溃」门在两条路径上结构性永绿**
`reg-sim.js:127`（`buyLottery`）、`:128`（`treatIllness`），`playtest-run.js:370 / :372` 同。
这两条路径**抛任何异常都会被吞掉**，既不计 crash，也不告警 —— 即使彩票/医疗 100% 抛错，
REG-00「1000 局零崩溃」仍然绿。这是 F-01 同型的永绿门，只是范围小一些。
→ 建议：改为记录到 `rec.swallowed[]`，REG-00 增加一条「静默吞异常次数 = 0」。

**F-11 🟡 REG-00 的 NaN 扫描覆盖面窄**
目前只扫 `st.stats` 的数值字段 + `netWorth` + `score`。
未覆盖：`career.years`、`edu.salaryK`、市场价格（`housePrice` / `stockPrice`）、贷款余额。
按 `nan-probe.md` 的实测，`borrow` / `repayLoan` / `buyStock` / `sellStock` / `repayDebt`
在脏入参下会让 `MONEY` 变 NaN（`MONEY` 在 `stats` 里，所以**恰好被覆盖**），
但同样的污染若发生在未覆盖字段上，门会继续绿。
→ 建议：改成递归走一遍 `state`（限深 6、限 5000 节点），任一 `number` 非 finite 即记脏局。

**F-12 🟡 除 REG-11 外，所有用 `runs()` 的用例都没有「有效样本量」断言**
REG-01 / REG-04 / REG-06 / REG-12 崩一批局之后，剩余样本可能只剩个位数，
统计门照旧输出 PASS/FAIL 且看不出样本已经塌了。REG-11 有 `minCell ≥ 30`，是唯一例外。
→ 建议：`runs()` 返回值里带 `crash`，各用例统一加一条「有效样本 ≥ 90% N」的前置断言。

**F-13 🟡 REG-00 的可复现性自检不在 try 里**
`makeRealSave()`（:153）在 try/catch 之外；一旦抛异常，整条 REG-00 变成「执行异常 0/1」，
三条断言的结果**全部丢失**（`crash-step` 注入已实证）。
→ 建议：包进 try，失败按「可复现性门红」处理，而不是让整条用例崩掉。

**F-14 🟡 REG-10 的 5 条「实测/静态」行没标「参考」**
断言名是 `rider 实测/静态`、`ai 实测/静态` …，实质是 `R.ok(true, ...)`（永远绿），
但名字里没有「参考 / 观察项」字样，机器和人都容易读成门。
准入矩阵已把它们判为「注入后仍绿 —— 永绿门」。
→ 建议：改名 `（参考）rider 实测/静态`。

**F-15 🟡 REG-06 的「全年龄空转率」是稀释门**
全年龄 **0.13（绿）**，但同一份数据里 **66-100 岁是 0.49（红）**。
分母被早年稀释，群体平均抹平了条件性断层 —— 与 D-1 是同一类错误。
→ 建议：主门改为「**各年龄段空转率的最大值** ≤ 0.20」，全年龄值降级为参考。

**F-16 🟡 REG-05「forceEnd 不应作为最终结局」也应标为守卫**
F-02 只裁了 `viaEndings`，漏了这一条 —— 它与 `viaEndings` 同性质：S-04 后恒真，
只有 S-04 被回退时才会红（`forceend-restore` 注入已实证）。
→ 建议：同样标注「守卫」。

3. 分母换成**职业收入中位**（低噪声）而不是终局净资产。

### 3.3 同年双触发的漏网路径（代码级）

```js
// assets/engine.js:1051-1068
const count = state.age <= 12 ? 1 : (chance(0.35) ? 2 : 1);
const picked = [];
const era = weighted.filter(x => x.ev.era);
if (era.length) {
  const e = era[randInt(0, era.length - 1)].ev;
  picked.push(e);
  weighted.splice(weighted.findIndex(x => x.ev === e), 1);   // ← 只移走被选中这一条
}
for (let i = picked.length; i < count && weighted.length; i++) { /* ← 其余 era 仍在池里 */ }
```

13 岁以上每年 35% 概率抽第 2 条 → 第 2 抽**可能正好命中同窗口的另一条 era**。

实测（`pickEvents()` 3131 次采样）：

| 单次返回 era 条数 | 次数（某次运行） | 占比 |
|---|---:|---:|
| 0 | 2440 | 77.9% |
| 1 | 684~690 | 21.9%~22.0% |
| **2** | **1~7** | **0.03%~0.22%** |

> 双触发是稀有事件，多次运行的计数在 1~7 之间波动（取决于 `chance(0.35)` 与权重抽样）。
> 结论的稳健部分是：**这条路径存在**，不是"从不发生"。

**修复（2 行）**：
```js
if (era.length) {
  const e = era[randInt(0, era.length - 1)].ev;
  picked.push(e);
  for (let i = weighted.length - 1; i >= 0; i--) if (weighted[i].ev.era) weighted.splice(i, 1);
}
```

### 3.4 跨年重复才是真问题（400 局实测）

`used` 保证每个 id 一生一次，但窗口是 **2 年** → 第 1 年命中 A，第 2 年 A 已入 `used`，B 仍在窗口内 → **第 2 年必触发 B**。

| 窗口 | 一生实际触发 ≥2 条的局占比（多次运行区间） |
|---|---|
| 1997-1998（+ 链式 `e1998gold`） | **78%~82%** |
| 2002-2003 | **96%~98%** |
| 2008-2009 | **93%~95%** |
| 2012-2013 | **93%~97%** |
| 2020-2021 | **94%~97%** |

连续两年触发「同窗口不同 id」的实测（400 局共 **1339~1457 次**，**平均每局 3.35~3.64 次**）：

| 序列 | 次数（某次运行） |
|---|---:|
| `x_e03` → `e2020` / `e2020` → `x_e03` | 158 / 156 |
| `e2012gangnam` → `x_e05` / `x_e05` → `e2012gangnam` | 146 / 140 |

| `e2008` → `x_e02` / `x_e02` → `e2008` | 133 / 127 |

**这意味着：一个活到 80 岁、经历过 1997/2002/2008/2012/2020 的玩家，平均会有 3.4~3.6 次"这事儿去年不是刚演过吗"的体验。**

## 4. 追加验证 B · NaN 根因定位

### 4.1 一句话结论

> **正常玩法不产 NaN（300 局零脏值、零崩溃）。**
> R-05 的真正源头是**输入层没有净化**：6 个金额入口的守卫用的是 `if (x <= 0) return` / `if (x > max) return`，
> 而 **`NaN <= 0` 和 `NaN > max` 都是 `false`** —— NaN 直接穿过守卫，把 `MONEY` 永久污染成 NaN。

### 4.2 三条基础事实（决定了 NaN 能否扩散）

| 表达式 | 结果 |
|---|---|
| `NaN <= 0` | **false** → `if (x <= 0) return` 拦不住 |
| `NaN > max` | **false** → 上限守卫也拦不住 |
| `clamp(NaN, 0, 100)` | **NaN** → 引擎的 `clamp` 不是 NaN 守卫（`Math.max(a, Math.min(b, v))`） |

### 4.3 定向复现：16 组「脏入参 → 数值污染」

| 入口 | 位置 | 会被污染的入参 | 调用后 MONEY |
|---|---|---|---|
| `borrow(state, id, amount)` | loan.js:82 | NaN / undefined / `'abc'` | **NaN** |
| `repayLoan(state, idx, amount)` | loan.js:109 | NaN / undefined / `'abc'` | **NaN** |
| `buyStock(state, id, shares)` | market.js:464 | NaN / undefined / `'abc'` | **NaN** |
| `sellStock(state, id, shares)` | market.js:481 | NaN / undefined / `'abc'` | **NaN** |
| `repayDebt(state, amount)` | market.js:498 | NaN / undefined / `'abc'` | **NaN** |
| `buyProp(…, qty)` | market.js:414 | `'abc'`（**`qty \|\| 1` 挡不住非空字符串**） | **NaN** |
| `buyProp(…, downRatio, …)` | market.js:414 | 无（安全） | 正常 |

`null` / `''` / `Infinity` 是安全的：`Math.round(null)` = 0 被 `<=0` 拦下；`Infinity` 被 `> max` 拦下。

### 4.4 传播链（实测）

```
buyStock(id, NaN)
  → state.stats.MONEY  = NaN   （不可逆：之后所有算术都是 NaN）
  → netWorth()         = NaN
  → scoreOf()          = NaN    ← Math.sqrt(Math.max(0, NaN)) 不会被吞
  → fmtMoney(MONEY)    = "0元"  ← (NaN || 0) 把 NaN 吞成 0
```

**这就解释了一个之前对不上的现象**：R-05 的 A 组同时报告了 `HP → NaN` 和 `MONEY → Infinity` 两种症状。
原因是 `fmtMoney()` 会把 NaN 悄悄显示成「0元」，而 HUD 上的 HP 是裸数字 → **金额看着正常、属性显示 NaN**。

### 4.5 定级

| 类别 | 定义 | 实测 | 归属 |
|---|---|---|---|
| **A 类 · 正常玩法可达** | 玩家正常 UI 操作就能产生 | **0 条**（300 局追踪） | — |
| **B 类 · 脏存档 / 畸形输入可达** | 导入旧存档码、老 localStorage、UI 输入框解析失败 | **16 + 3 = 19 条** | **本条（A-11）+ R-01 / R-09** |
| **C 类 · 仅直接注入可达** | 只能手写 STATE 产生（robustness-review A 组的做法） | 存在，但**不是玩法缺陷** | UI 出口 `num()` 已修 |

**最可能的真实触发路径**：

1. **UI 数量输入框留空 / 输入非数字** → `parseInt` 得 NaN → 传给 5 个买卖/借贷入口 → **现金当场变 NaN，不可逆**。
   玩家看到"钱变 0 了"，实际是整局数值已废。
2. **导入旧版存档码**（R-09 只校验 `obj.stats` 存在）→ loan 的 `principal` / `years` 缺失 → `annualPayment` 的 `l.principal / l.years` 得 NaN/Infinity → `loanTick` 里 `MONEY -= NaN`。
3. **老 localStorage 存档缺字段**（R-01 域）→ 迁移后 `market.stocks[i].shares` 为 undefined → `stockValue` NaN → `netWorth` NaN → `scoreOf` NaN。

### 4.6 建议修复（共约 10 行）

```js
// (1) engine.js 顶部，clamp 旁边
function safeNum(v, fb) { const n = Number(v); return Number.isFinite(n) ? n : (fb === undefined ? 0 : fb); }

// (2) 六个入口第一行净化
const amt = safeNum(amount, 0);
const n   = Math.floor(safeNum(shares, 0));
const q   = Math.max(1, Math.floor(safeNum(qty, 1)));

// (3) loan.js annualPayment
const per = l.principal / Math.max(1, l.years);

// (4) marketMigrate 顺手消毒持股
m.stocks = (m.stocks || []).map(p => ({ id: p.id, shares: safeNum(p.shares,0), cost: safeNum(p.cost,0) }))
                           .filter(p => p.id && p.shares > 0);
```

> **与 engineering-lead 的 `num()` 不冲突、不可替代**：`num()` 只在 UI 出口让 NaN 不显示，
> 但玩家的**存档此时已经是脏的**，下次读档照样炸。第 (2) 条才是根治。

**验收**：`probe-nan.js` §1 命中数 16 → 0；§4 运行时追踪保持 0。
