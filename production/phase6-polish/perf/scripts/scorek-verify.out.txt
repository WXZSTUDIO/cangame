## 1. 验证主张：二本 1.045 > 一本 1.04

- 二本 `need`=392，封顶分 = 392+70 = 462 → 封顶后 `salaryK` = 0.95 × 1.1 = **1.045**
- 一本 `need`=476，压线 `salaryK` = **1.040**
- 判定：**反转成立 ✓**（1.045 > 1.040）
- 受影响分数段：gao ∈ [462, 475]
  → 这段里玩家**只能上二本**（一本还差 14 分），拿到 1.045；
  → 一旦考到 476 分能上一本了，反而只剩 1.040。
  → **考得更好、拿得更少，主导策略反转 — 他的判断是对的。**

## 3. `bestSalaryKFor(gao)` 参考实现（可直接抄进 school.js）

```js
/* 档内连续化：超线每 70 分 +10% 起薪，封顶 +10%（SCORE_K） */
const SCORE_K = { over: 70, max: 0.10 };
function uniNeed(u) { return Math.round((u.minScore || 0) / 100 * 700); }
function scoreKFor(u, gao) {
  return 1 + clamp(Math.max(0, (gao || 0) - uniNeed(u)) / SCORE_K.over, 0, 1) * SCORE_K.max;
}
function salaryKFor(u, gao) { return u.salaryK * scoreKFor(u, gao); }
/* 纯函数：QA 直接注入整数分直读，绕开 11 年随机过程 */
function bestSalaryKFor(gao) {
  let best = null;
  UNIVERSITIES.forEach(u => {
    if ((gao || 0) < uniNeed(u)) return;              // 够不到
    if (u.id === 'u_fail') return;                    // E-12：落榜档不参与连续化
    const k = salaryKFor(u, gao);
    if (!best || k > best.k) best = { uni: u.id, k: k };
  });
  return best;   // { uni, k } 或 null
}
```

`applySchool`（school.js:418）改为：
```js
e.salaryK = (u.id === 'u_fail') ? u.salaryK : salaryKFor(u, e.gao);
```

## 4. `salaryK` 上限与 ERA 叠加后的余量

- `assets/` 里**目前没有任何对 salaryK 的 clamp**（grep `clamp(salaryK` 无命中）
- `economy-respec.md` U-5 的 `clamp(salaryK, 0.8, 1.60)` 是**尚未实现的提案**

| 情形 | salaryK | 距 1.60 余量 |
|---|---:|---:|
| 985 压线 | 1.420 | 12.7% |
| 985 超线封顶（×1.1） | **1.562** | **2.4%** |
| 985 考研上岸（`Math.max(k, 1.45)`） | 1.562 | 2.4% |

> design-strategist 说「最高到 1.562，距 1.60 只差 4%」。实测：985 压线 1.42 × 封顶 1.10 = **1.562**，距 1.60 余量 **2.4%**。
> 他报的 1.562 应该是 1.42 × 1.10 = 1.562 —— **对得上 ✓**（我这里是 1.5620）。

## 5. 顺带发现：`考研上岸` 有两个不同的下限值

| 位置 | 触发路径 | 取值 |
|---|---|---:|
| `school.js:459` | 校内活动 `a_kaoyan` | `Math.max(salaryK, 1.4)` | **1.40** |
| `engine.js:2101` | 毕业选择 `grad_at_*` | `Math.max(salaryK, 1.45)` | **1.45** |
| `engine.js:2129` | 再考一次 `kaoyan2_at_*` | `Math.max(salaryK, 1.45)` | **1.45** |

**同一个「考研上岸」语义，两个下限。** 985 生（salaryK 1.42）走不同路径结果不同：
- 走校内考研活动：`Math.max(1.42, 1.4)` = **1.42**（不变）
- 走毕业选择考研：`Math.max(1.42, 1.45)` = **1.45**（+2.1%）
- `career.js:571` 的注释里两个值都记了（「或考研上岸后的 1.4 / 1.45」），说明这个不一致是**已知的、但没统一**

这不在你 E-11 的范围里（E-11 说的是「考研与 scoreK 无冲突」，那条我认同，`Math.max` 取下限不是相乘，确实不用改）。但**两个值不一致**是另一回事，建议顺手统一。
