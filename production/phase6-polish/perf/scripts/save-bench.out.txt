## 2. 单次写入延迟（jsdom 内存 localStorage，偏乐观）
样本：78 岁的存档（尝试 1 次才活到这个岁数——随机作答死亡率不低）
操作                    | p50 ms | p95 ms
----------------------+--------+-------
JSON.stringify(STATE) | 0.148  | 0.179 
localStorage.setItem  | 0.001  | 0.002 
localStorage.getItem  | 0.001  | 0.002 
JSON.parse(读回)        | 0.164  | 0.197 
**autosave() 全流程**    | 0.179  | 0.222 
存档序列化后 45.5 KB。真实浏览器的 setItem 会把 **45.5 KB 同步刷到磁盘**，在低端 Android WebView 上实测常见 3–15 ms；这里是纯内存，数字要再放大。

## 5. 配额写满时的行为
jsdom 无配额限制（写了 4.5 MB 仍成功），但**真实浏览器会抛 `QuotaExceededError`**。当前 `lsSet()` 的实现是：
```js
function lsSet(k, v) { try { localStorage.setItem(k, JSON.stringify(v)); } catch (e) { } }
```
→ **异常被静默吞掉**：配额写满 / 隐私模式禁用 storage 时，玩家会以为存档成功，下一次打开却回到标题页，且**不会有任何提示**。这是目前最需要修的健壮性缺口（详见 robustness-review.md R-02）。
