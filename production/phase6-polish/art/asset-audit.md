## 1. 头像系统实测检视结论

### 1.1 结构层面：干净

`structure: 212/212 clean` —— 12 名字 × 2 性别 × 8 年龄 + 20 强制发型组合，**无 NaN / undefined / 结构畸形**。此前修过的三处（微卷卷圈浮空、小孩发际点悬空、男女渐变 id 串色）在实测中**均未复现**：

- 渐变 id 冲突：`uid = 'pg' + (h%46657).toString(36) + ((h>>>7)%89)`，同名同性别同 uid、同名不同性别不同 uid，跨人哈希分散度足够，未见串色。
- 微卷（M style 7/8）：卷圈四颗圆（r 2.7–3.1）落在发际线弧上，未浮空。
- 小孩发际：`kid` 分支发际点与 `ring` 叠合正常。

### 1.2 视觉层面：发现 6 项问题

按严重度排序：

| # | 问题 | 位置 | 证据 | 严重度 |
| --- | --- | --- | --- | --- |
| P1 | **性别辨识度弱**：多张女性头像（F style 0–5）轮廓与男性短发高度相似，正面无双耳外露、肩线一致，远看难分男女 | `portraitSVG` 女 `st<=5` 长发分支 vs 男短发 | grid-f-styles 第 1 行 vs grid-m-styles | 中 |
| P2 | **成年人脸型偏「娃娃脸」**：`rx=21.5 / ry=26` 的脸型 + 低垂下颌 + 大眼（`rx 3.7 / ry 2.35`）比例接近幼态，与「韩系证件照」的成熟写实定位有落差 | `portraitSVG` 脸/眼几何 | grid-ages age 25/40 与 age 6/12 差异很小 | 中 |
| P3 | **老年「老年感」偏弱**：白发 + 老花镜 + 轻皱纹已到位，但脸型/嘴型几乎不变，`elder` 仅加额纹，**缺眼袋、法令纹、皮肤松弛**，85 岁与 58 岁视觉差异有限 | `wrinkleBrow` / `wrinkle` / `old` 分支 | grid-ages age 58/72/85 | 低 |
| P4 | **发色明度整体偏深、彼此接近**：`P_HAIR_F` 6 套 / `P_HAIR_M` 5 套在深棕区间扎堆，同一屏多人时发色肉眼几不可分 | `P_HAIR_F`/`P_HAIR_M` 常量 | grid-people 第 2 行 4 人发色几乎一致 | 低 |
| P5 | **背景渐变 6 套差异化不足**：`P_BG` 均为极低饱和暖/冷白，卡池同屏时背景「撞色」，人物区分度只能靠发型 | `P_BG` | grid-people 第 1 行 | 低 |
| P6 | **眼镜为纯装饰、非语义**：`(h>>>5)%6===0 || old` 随机戴镜，与「知识分子/老年」设定无关，可能出现 8 岁小孩戴老花镜的观感（`kid` 未排除戴镜分支）| `glass` 分支 | 代码：`glass` 条件未 `&& !kid` | 低 |

> **注**：P6 经代码确认——`glass` 计算式为 `((h>>>5)%6===0)||old`，**未排除 kid**。8 岁以下 1/6 概率戴镜，与年龄气质冲突。属真实缺陷，但非本 Phase 的阻塞项。

### 1.3 「相机一致」校验（重要，已通过）

`grid-people.png` 中同一名字跨年龄呈现**同一张脸的不同年龄**，`hashStr(name|gender)` 保证种子确定性、`portraitSVG` 不依赖 `STATE`，因此**换装/推进年份不会换脸**，这是本系统设计正确的地方，务必在后续任何改动中**保持哈希确定性契约**。

## 2. 头像 vs 整体「贴纸卡通风」的风格冲突（核心议题）

### 2.1 现状诊断

游戏其余部分是 **v5.1 定的高饱和贴纸卡通**：`--ink #100F06` 粗黑描边（2–2.5px）+ 硬阴影（`0 3px 0 var(--ink)`）+ 高饱和色块（Gold `#FFDA57` / Pink `#FFBBF4` / Malibu `#7DCAF6`）。

而 v5.5 新头像走的是 **韩系影楼证件照**：柔和径向渐变肤质、零描边、低饱和暖调、写实五官。

**两者在「描边语言」「饱和度语言」「明度语言」三个维度上完全相反**，同框时（如 `.rel-card` 里圆形头像 + 黑描边卡片）头像显得「照片贴在贴纸墙上」。

### 2.2 调和方案（三选一，建议方案 B）

| 方案 | 做法 | 工作量 | 一致性 | 冒险度 |
| --- | --- | --- | --- | --- |
| **A. 全量卡通化** | 给头像加 `--ink` 描边轮廓、硬阴影、提高饱和 | 大（重画 20 发型） | 最高 | 推翻 v5.5 重做成果，**不建议** |
| **B. 头像加「贴纸外壳」（推荐）** | **保留头像内部写实**，在承载容器 `.rel-ava.pic` / `.hud-avatar` 上包一圈 **3px `--ink` 描边 + `0 3px 0 var(--ink)` 硬阴影**，把头像当作「一张贴纸照片」嵌入体系 | **小（纯 CSS，~6 行）** | 高 | 低，不动 SVG |
| **C. 增设「风格化」开关** | 头像内部再叠一层轻描边（发丝/脸缘 `stroke: var(--ink) opacity .25`） | 中（JS+CSS） | 中 | 中 |

**方案 B 落地改法（交主理人排期，属 CSS 层）**：

```css
/* style.css · 覆盖现有 .rel-ava.pic / .hud-avatar */
.rel-ava.pic{border-width:3px; box-shadow:0 3px 0 var(--ink)}   /* 现为 2px 无阴影 */
.hud-avatar{border-width:3px; box-shadow:0 3px 0 var(--ink)}   /* 现为 2px #fff */
```

`HUD` 头像现为 `border:2px solid #fff`——在深色 HUD 上白边虽可读，但**丢失了体系的「黑描边」语言**，建议改为 **外层 `--ink` 描边 + 内层白环** 或直接 `3px solid #fff` 保持 HUD 内对比（HUD 是深底，白边在此处合理，列为「可接受例外」并记录到美术圣经）。

### 2.3 结论

风格打架**真实存在但不严重**，根因是「头像缺一个统一的、属于本作品的边框语言」。**推荐方案 B**，以最低成本把头像纳入贴纸体系，且不推翻 v5.5 成果。此项**列为视觉 Top 1 优先修复**。

## 3. UI 色板一致性审计

### 3.1 达标部分

- `style.css` 顶部定义 **完整 CSS 变量色板**（`--paper/--ink/--gold/--teal/--blue/--lav/--pink/--red/--green` 及各自 `-d`/`-l` 变体），**绝大多数组件通过 `var()` 引用**，这是很好的基础。
- 涨红跌绿采用中国习惯（`--red` 涨、`--green` 跌），且**市场模块同时输出 `+`/`−` 符号**（`ui.js:1752/1782/1799`），**颜色之外有无障碍冗余线索**，符合 WCAG 1.4.1「不单靠颜色传达信息」。这是本作一个隐藏亮点，应在美术圣经中**固化为规范**。

### 3.2 散落硬编码色值（破坏体系，需收敛）

| 类别 | 具体值 | 位置 | 问题 |
| --- | --- | --- | --- |
| **中性灰未变量化** | `#6F6D5E`（正文灰）、`#B4B1A0`（弱化灰）、`#C9C6B6`（箭头灰） | `style.css` 多处（`.lead/.line/.foot/.of-meta/.ladder .arrow` 等 ~10 处） | 未进 `:root`，语义相同却各写各的，未来改色要全量替换 |
| **头像调色板** | `P_SKIN/P_HAIR/P_LIPS/P_BG/P_CLOTH` 等 31 组色值 | `ui.js:383–400` | 头像自成体系**可以接受**，但**应为「头像专用 sub-palette」并注释「不参与 UI 色板」**，目前无此标注，易被误当 UI 色 |
| **头像内部一次性色** | `#D9A08A/#FDFBF8/#191009/#241A12/#4A3527/#8A5C42/#A65B50/#F0A091/#E8C36A/#39322C/#D9D5CE/#C6C1BA/#241708` 等 ~15 处 | `ui.js` 头像各分支 | 属头像绘制细节，可接受，但**应集中为常量**（如 `TONE` 对象）便于统一调色 |
| **内联 var 引用混杂** | `style="color:var(--red)"` | `ui.js:719/720/776/777/1035` | 方向正确（用变量），但**内联 style 破坏了关注点分离**，理想应改 class（`.val-neg`）。属可接受技术债 |

### 3.3 色板应用结论

**整体一致，无「随机硬编码色破坏体系」的严重违规**，但存在 **3 组中性灰未变量化 + 头像色板未标注边界** 两类可收敛项。建议在美术圣经 §2 明确「UI 色板」与「头像 sub-palette」的边界，并把三组灰补进 `:root`。

## 4. 图标 / emoji 使用审计

### 4.1 现状

- **共 136 个 emoji、64 个去重 emoji**，分散在 `ui.js(65) / data.js(35) / school.js(21) / engine.js(7) / loan.js(6) / career.js(2)`。
- 承担：HUD 状态图标（💵🏦💾）、dock 导航（💼📈🛍👥）、标签徽章（🎓🏫💼🏅）、成就图标、事件装饰、年龄表情（`ageAvatar` 返回 👶👧👦👩🧑👩‍💼👨‍💼👵👴）。

### 4.2 问题

| # | 问题 | 说明 |
| --- | --- | --- |
| E1 | **同一语义多字形**：如成人女 `👩`/`👩‍💼`、成人男 `🧑`/`👨‍💼`、老年 `👵`/`👴` 与卡片性别混用；「工作」dock 用 💼，状态标签也用 💼 | 语义未收敛，缺少「图标字典」 |
| E2 | **裸 emoji 作唯一视觉载体**：dock 的 `.d-ic` 只有 emoji + 文字，**无障碍名为空**（见可访问性报告 A-04） | 与无障碍交叉 |
| E3 | **emoji 跨平台渲染不一致**：Windows Segoe / Android Noto / iOS Apple 三套皮，高饱和贴纸体系下 emoji 的调性不受控 | 属平台风险，非缺陷 |
| E4 | **`️`(U+FE0F) 单独出现 1 次**（变体选择符残留） | 疑似 `⚠️` 拆分残留，需核查 |

### 4.3 建议

不做「去 emoji 化」（那是推翻式改动）。**建立「图标字典」文档**：把 64 个去重 emoji 归入 6 类语义槽（货币/状态/职业/学业/关系/系统），**每槽固定 1 个首选字形**，禁止同槽异形。此项列入资产规格 §5。

## 6. 门控判定

### **CONCERNS**

**理由**：
1. **结构性 O，无硬故障**：头像 212/212 clean；色板整体通过 CSS 变量收敛；市场涨跌已带 `+/−` 冗余。基础健康。
2. **但存在 1 项高严重度无障碍缺陷**（AR-03 弱化文字对比 <3:1 FAIL）、**1 项高严重度色觉风险**（AR-02 红绿明度比 1.04）、以及**系统性无障碍缺失**（AR-04/05/06，全站零 `aria`/`role`/`reduced-motion`）。
3. 视觉层面**没有阻塞上线的破损**，风格冲突（AR-01）可由 ≤6 行 CSS 修复。

**未判 FAIL 的原因**：所有问题**均可增量修复**，无需重构；头像系统核心契约（哈希确定性、无 NaN）完好。

**转为 PASS 的条件**：修复 AR-01 / AR-02 / AR-03 三项后重测即可。

## 7. 附录：对比度计算脚本

```js
function hex2rgb(h){h=h.replace('#','');if(h.length===3)h=h.split('').map(c=>c+c).join('');
  return [parseInt(h.slice(0,2),16),parseInt(h.slice(2,4),16),parseInt(h.slice(4,6),16)];}
function lin(c){c/=255;return c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4);}
function L(rgb){return 0.2126*lin(rgb[0])+0.7152*lin(rgb[1])+0.0722*lin(rgb[2]);}
function ratio(a,b){const la=L(hex2rgb(a)),lb=L(hex2rgb(b));
  const hi=Math.max(la,lb),lo=Math.min(la,lb);return (hi+0.05)/(lo+0.05);}
```

关键结果见 `accessibility.md` §2。
